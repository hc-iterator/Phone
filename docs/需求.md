## 一、产品需求（最终要做成什么）

### 总目标

用**现在的 3.5 寸 HDMI 屏** + **RP2350B（微雪的 RP2350-PiZero）**
搭一个**能显示的简单手机系统**。

### 中心思想（用户原话）

> "中心思想就是 FreeRTOS 调度，内核掌握所有外延（屏幕啊蓝牙啊内存啊）的权限，
> 通过系统 API [分发]，应用尝试访问就会触发内存越权报错，
> 系统在报错中判断这是'合法'报错后执行相应操作后返回。"

**拆成三条：**
1. 有调度（FreeRTOS 思路：单前台 + 多后台应用）。
2. **内核掌握所有外设的权限**，通过系统 API 分发。
3. **"越权报错即系统调用"**：应用去碰它没权限的东西会触发异常，
   内核在异常处理里判断"这是一次合法调用"，执行完再让应用继续。

### 系统调用 ABI（用户原话）

> "应用函数就是按着 4 字节对齐一个个摆在这里…`void sys_call_func ()=0x0001;`"

即：
- 有一个"系统页"，里面按 4 字节一个槽位排列各系统调用；
- **系统页对应用是 MPU 只读的**；
- 应用**写第 N 个槽**就等于发起第 N 号系统调用（写动作触发越权异常）。

（正式 ABI 条文在 `docs/应用ABI.md`；机制全文见该文件附录。）

### 要有哪些应用

| 应用 | 要求 |
|---|---|
| 单前台 + 多后台 | 这是调度的基本形态 |
| 蓝牙 / 2.4G 组网 | **文字 + 表情包** |
| 2048 | 游戏 |
| 黄金矿工 | 游戏 |
| 文本浏览器 | 浏览文本内容 |

### 其它硬指标

- **总花费 ≤ 300 元**
- **外壳自己建模**（3D 打印）

## 二、整体架构（用户 2026-09-29 定的方向）

> **用户原话：**
> **"首先定整体架构。现在的设备叫技术验证，完了以后肯定要打板。
> 如果有冲突设计到无法兼容，可以考虑弄一个 RP2040 当副核，
> 和 RP2350B 做 SPI 通信（SDIO 的 SD 卡不占 SPI 口，SPI 现在很空）。
> 由于位于同一块 PCB 上，SPI 分频可以不分就直接主频用，
> 这样的话速度算是够用。记下。"**

**四条要点：**

1. **现在的设备叫「技术验证」**，之后**肯定要打板**。
2. 遇到**"设计到无法兼容"**的冲突时，**可以考虑加一颗 RP2040 当副核**，走 SPI。
3. **SD 卡走 SDIO，不占 SPI** ⇒ **SPI 现在是空的**。
4. 同一块 PCB ⇒ **SPI 可以不分频、直接跑主频**，速度够用。

**架构本身写在 `docs/总体架构.md` §A**（含两个阶段对照、总线分配、副核方案的带宽核算与风险）。

**由这条推出的硬要求（重要）：**
> **硬件差异必须关在一层"板级支持层（BSP）"里** —— 否则打板时整个内核要重写。
> 见 `docs/总体架构.md` §A.1。

## 三、第一档五个方向（用户 2026-09-29 定）

> **用户原话：**
> **1. FreeRTOS 和内存锁冲突，顶多在副核上跑，主核必须自研。**
> **2. 应用可以有多个"进程"。**
> **3. 系统应用的哈希直接写死在同一代的内核里。**
> **4. 副核目前看是可选项而非必选项。**
> **5. 目标：启动时间 30s 以内或 1min 以内，帧率 60fps，内存的话自己打板想做多少做多少吗？技术支持多接几个 PSRAM 吗？**

### 五条的记录与推论（⚠️ 右栏是**我的推论**，不是用户原话）

| # | 【用户定】 | 推论（待确认） |
|---|---|---|
| 1 | **主核自研调度；FreeRTOS 顶多上副核**（理由：FreeRTOS 与内存锁冲突） | 自研内容：任务控制块、**PendSV 上下文切换**、时间片、优先级、阻塞唤醒。<br>✅ 与内存归宿吻合：**MSP 在 SRAM（中断）、PSP 在 PSRAM（任务）** |
| 2 | **应用可以有多个"进程"** | ⚠️ **撞 MPU 区域预算**（共 8 个）。<br>⇒ **建议：同一应用的多个进程【共享一个 MPU 区域】**（同地址空间、各自栈）<br>⇒ 代价：应用内部进程间无隔离（同一信任域，可接受） |
| 3 | **系统应用哈希写死在同一代内核里** | ⇒ 这就是**权限授予机制**；"同一代"= 换内核则老系统应用失效，必须一起更新。<br>⚠️ **不签名的话，谁能改内核谁就能改哈希表**。<br>✅ **2026-09-29 查证：RP2350 【有 SHA-256 硬件加速器，而且能挂 DMA】**（`hardware_sha256` 的 `sha256_set_dma_size()`）⇒ 加载时算哈希**几乎不占 CPU**，还能和 SD 读取并行 ⇒ **这条机制几乎白送**。<br>另外还有 **TRNG（真随机数）**。RP2350 也支持**安全启动**（验签 boot2 + OTP 存密钥哈希）⇒ 哈希表可被**硬件信任根**锚住（**要不要用待定**，代价是 OTP 一次性烧写）。<br>证据与 API 见 `docs/实测数据.md` §八。 |
| 4 | **副核是可选项，非必选** | ⇒ 自打板**预留焊盘/引脚，但不装也能跑**；**固件不许依赖副核**（承重功能绝不放它上面） |
| 5 | **启动 ≤ 30 s（或 ≤ 1 min）；帧率 60 fps** | 见下方目标表 |

### 目标（建议当判据，以后所有取舍拿它量）

| 指标 | 目标 | 评估 |
|---|---|---|
| **启动时间** | **≤ 30 s**（用户给的；可放宽到 1 min） | 对 MCU **极宽松**（正常应 < 1–3 s）。⚠️ 太宽松会让"启动慢"看起来合法。<br>吃时间的大头：**SD 卡挂载**（大卡扫 FAT 表）、**PSRAM 上电校准**、**应用加载**。<br>⇒ 建议自加一条：**内核到"能显示画面"控制在 1 秒内；应用按需加载** |
| **帧率** | **60 fps** | ✅ 与设计自洽：300 KB × 60 = **18.4 MB/s**，在 PSRAM 上限 37.5 MB/s 内 |
| **内存** | 用户问"自己打板想做多少做多少？能多接几颗 PSRAM？" | ❌ **不能**：能当 RAM 用的 PSRAM **只有一颗**（QMI 只有 M0/M1 两套时序引擎）。<br>⚠️ 而且**墙是带宽不是容量** —— 多加一颗也**共享同一条 QSPI 总线**，带宽不涨。<br>⇒ 提带宽的两条：**提高 PSRAM 时钟**（现在 clkdiv=2）、**减少流量**（损伤修复） |

## 四、内核需求（用户 2026-09-27 明确的新阶段目标）

> 原话：
> **"停！现在你的目标是：建立好完整的系统内核，能够分配内存，PSRAM，SD卡资源，
> 协调 PIO，DMA 等"**

拆开就是五件事：

1. **内存分配** —— 内核要有自己的内存管理器，能分给应用。
2. **PSRAM 资源** —— 板上 8 MiB 要能用起来。
3. **SD 卡资源** —— SD 要能作为资源被管理（应用从 SD 加载）。
4. **协调 PIO** —— PIO 状态机要由内核统一分配，不能谁想用就用。
5. **协调 DMA** —— 同上，DMA 通道也要内核分配。

> 用户对"屏幕"的定位（原话大意）：
> **"屏幕充其量也只能算个大号外设，搭好内核才是地基。"**

## 五、硬件需求与约束

> **正式的硬件决策条文在 `docs/硬件设计.md`**（含电源架构、输入口、调试触点、打板清单）。
> 本节只留**用户定下的硬约束摘要**，细节不重复。

### 必须自己打板（用户已表态）

理由（用户给的）：
- **SDIO 不能丢** —— 应用是 `.bin` 从 SD 卡加载的，这是承重墙，不是可选项。
- 外部接线接 HDMI / SDIO **不可用**。
- 要自建模外壳，所以板形要配合。

### 已定的硬件形态要点

- 主控 **RP2350B**
- **HSTX（GPIO12–19）→ HDMI/DVI**，四层板、100Ω 差分对、等长
- **SDIO 4 位全速** + 板载卡座
- 16MB **1.8V** QSPI flash + 16MB **1.8V quad** PSRAM 共用 QSPI ⇒ 两个都得是 1.8V
- ~~1.8V LDO 从 3V3 生成~~　⚠️ **已作废（2026-10-01 用户定）**：改走 **5V → 1.8V 直接 DC-DC**
- PSRAM 片选走分压（唯一跨电压域的信号线）
- ~~外部射频模块（ESP32-C3/C6 优先；RM2 不好买）~~　⚠️ **已作废**
  （2026-09-29 用户澄清：**从来只有 CYW43439 的 WiFi + 蓝牙，没有独立射频规划**）
- **无线 = CYW43439（WiFi + 蓝牙）**，峰值 **301 mA @ 3.3V**（datasheet 值）
  ⚠️ **已查证（2026-09-29，SDK 源码）**：**不是**走硬件 SPI，而是走 **PIO 实现的"魔改 SPI"**
  （`pico_cyw43_driver/cyw43_bus_pio_spi.c` + `.pio`，用 `pio_claim_free_sm_and_add_program_for_gpio_range()`）
  ⇒ **不占硬件 SPI**（PL022 两个实例都还在）✓
  ⇒ **但它占「PIO 的 1 个状态机 + 一段指令空间」** —— 资源表该扣的是这两样。
  ⚠️ **布局约束**：它的几根线要落在**同一个 PIO GPIO 窗口**内
  （源码注释："The pins should all work in the same gpio base"）。
- **打板必须走 SMT 贴片服务**：RP2350B 是 QFN-80（0.4 mm 脚距），手工焊不了 ⇒ 嘉立创。
  ⇒ 推论：**自打板改一版很贵** ⇒ **能在阶段 1 微雪板上验证完的，就别留到自打板上试。**
- **★ 调试/救援接口（用户 2026-10-04 定，别省）**：
  **BOOT 与 RUN 都要"按钮 + 触点/焊点"两套**（原话："一定要不仅弄个按钮，
  而且还要弄个触点或焊点给 boot 和 run"）——
  按钮给裸板随手用；**焊点/触点给"装壳后够不着"的情况（镊子/跳线/测试钩短接）**，
  也便于**焊线引到面板或排针**。
  标准进 BOOTSEL 手法 = **按住 BOOT → 点一下 RUN → 松开 BOOT** ⇒ **两个焊点缺一不可**。
  正式条文见 `docs/硬件设计.md` §1.4.1；背后教训见 `docs/陷阱.md` 错 26。

### 选型硬条件（用户要求：≤3mA 片选电流、走 1.5V 而不是 1.8V）

- PSRAM 分压最终取值 **R1=680Ω（上）/ R2=560Ω（下）**
  ⇒ 2.66 mA、输出 1.49 V、戴维南 307Ω、0603 上 8.8 mW
- **走 1.5V 而不是 1.8V** 的理由：CMOS 输入有到自身 VDD 的 ESD 钳位二极管，
  1.8V 目标 + 3V3 上偏 5% ⇒ 1.89V ≈ VDD+0.09V，会把钳位二极管正偏进 1.8V 轨。

## 已评估并否决：RISC-V（Hazard3）尝鲜

**结论：对当前目标没有必要 ✗；作为学习实验以后可做，但【不许 fork 主线】。**

**三条硬账（决定性）：**

1. **内核安全机制必须重写** —— 这是本项目的立身之本。
   ARM 路线用 `MPU 区域登记 + CONTROL.nPRIV + SVC + naked 处理程序`；
   Hazard3 用 `PMP + 特权模式 + ecall` ⇒ `kernel.c` 那套"内存越权触发异常请求服务"
   全部要重做 ⇒ 相当于拆掉摩天大厦的地基。
2. **`frank_tmds.S`（ARM Thumb 汇编，DVI 热路径）必须重写** ⇒ 而它正是余量最紧的一段。
3. **同频性能低于 M33**（约 0.7~0.9×），且要养两套工具链 ⇒ 与"可复现性优先"冲突。

**已核实的事实（2026-10-02）：**
* RP2350 **本身就带双核 Hazard3** ⇒ 尝 RISC-V 的**硬件成本 = 0 元**（同一颗芯片二选一启动）
* SDK **官方支持**：`cmake/preload/platforms/rp2350-riscv.cmake` 与
  `toolchains/pico_riscv_gcc.cmake`（`-mcpu=hazard3-rp2350`）
* 但**本地只装了 ARM 工具链** ⇒ 要另下 RISC-V 工具链（几百 MB）
* ⚠️ **架构选择涉及 OTP（一次性可编程、不可逆）** ⇒ 动手前必须读 SDK 的
