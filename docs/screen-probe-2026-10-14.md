# 屏幕侧测量与结论（2026-10-14）

> ## 证据来源三分法（本文每条结论都必须标来源）
>
> - 「**电脑**」= 用户 PC 链路：AMD R9 380 → 驱动（含 Oray 虚拟显示器 ✗）→ HDMI → 屏幕。**1080p**
> - 「**屏幕**」= KTC "W21.5HDMI" 自身的行为（缩放 / 压缩 / 面板）
> - 「**单片机**」= RP2350/PiZero 上**我们自己的固件**（HSTX + PIO0/PIO1 两级窗口中继 → 32-39）。输出 **640x480 静止 8 色竖条**
> - 「**未验证**」= 推断或假设，**没有证据** ✗
>
> ⚠️ 把这三者混用，就会把"电脑的问题"记成"我们的问题"（或反过来）✗ —— 所以本文逐条标注 ✓。
>
> **一句话结论**：撕裂**归因于屏幕自身**（用户差分排除 ✓，见 §2）；**单片机侧仍未被观察** ✗（见 §3）。

## 1. 已确证的事实

| # | 事实 | 来源 | 证据 |
|---|---|---|---|
| 1 | 场景切换时出现**斜向撕裂** | **电脑** | 用户实测：电脑直连 HDMI、1080p |
| 2 | **只有大面积色块变化时才撕裂**；静止时不撕 | **电脑** | 用户实测：全屏 `screen-test-bars.png` 只在**切入那一下**撕裂，之后一直完美 |
| 3 | 电脑与屏的**协调握手走 USB**（不走 HDMI） | **电脑** | 本机设备树：`USB\VID_26AE&PID_8506` = HID 触摸(COL01) + 供应商定义设备(COL02) |
| 4 | 电脑输出 1080p，屏幕自己做压缩 | **电脑** | 用户描述 + EDID：KTC 首选 1920x1080@60 |
| 5 | 台架那块屏是 KTC "W21.5HDMI"（2009, EDID 1.3） | **屏幕** | 注册表 EDID 解析；`DISPLAY\KTC2154` |
| 6 | 我们的固件输出 640x480 静止 8 色竖条 | **单片机（源码）** | `src/hstx_copy.c:67-72` 颜色表、`:74-84` scanline 回调、`:286-289` 初始化 |

## 2. 归因：**屏幕**（用户差分排除，2026-10-14 确认成立 ✓）

**证据链（排除法）**
1. 线材 ✓ 正常
2. 显卡 ✓ 正常 —— 同一台电脑/显卡**此前用 HDMI 输出过且正常** ✓
3. 换成这块屏 ⇒ 出现斜向撕裂 ✓；内容换成静止 ⇒ 不撕 ✓
⇒ 链路中唯一变化的变量是**屏幕** ⇒ **归因于屏幕（其自身处理链）成立** ✓

**我此前的更正** ✓：早前我写"电脑侧证不出是屏"属于**过度谨慎** ✗ ——
对工程判断而言，上面的差分排除已经足够 ✓（用户原话：「不是屏幕是谁的问题啊」✓）。

**仍未测的只是屏内部的具体环节**（HDMI 接收端？缩放器？压缩链？）✗ ——
这不影响归因，只影响"能不能修"：屏内部我们**改不了** ✗ ⇒ 只能按用户口径接受 ✓。

**机制假说**（**用户提出** ✓；触发条件已在电脑侧验证 ✓）：屏的压缩算力/带宽不足 ⇒ 内容变化大时码率峰值 ⇒ 撕裂 ✓。

## 3. 单片机侧：目前**零真机观察** ✗

- 我们的画面（640x480 静止 8 色竖条 ✓，见上表 #6）**从未上过任何屏幕** ✗ —— PiZero 一直没接上 ✓。
- ⇒ 关于"**单片机能不能出稳定画面**"，本文**没有任何结论** ✗。请不要拿电脑侧的结论替它下判断 ✓。
- 按电脑侧的模型只能**预期**（未验证 ✗）：静止图案 ⇒ 码率极低 ⇒ 应当稳定 ✓。

## 4. 验收口径（用户 2026-10-14 确认，**适用于单片机侧真机**）

> 原话："只有全屏这图像的时候撕裂了一下，然后显示一直完美。要是达到这种程度我就能接受了。"

⇒ **静止稳定 = 达标** ✓；切换大面积内容时偶发一次 = 可接受 ✓；**持续撕裂 / 闪烁 = 不达标** ✗。

| 单片机真机看到 | 含义（均指单片机侧） | 下一步 |
|---|---|---|
| 8 色竖条稳定、颜色正确 ✓ | **达标** ✓ | 归档收工 |
| 全黑 ✗ | 没出图：HSTX 未起 / 时序 / 供电 | 先 `R` 重启；再 `W`/`P` 看三级活动度 |
| 颜色错（红蓝互换之类） | 单片机侧 D0/D2 顺序反了 | 改 stage-1 的 `in_pin` 排列（机制不动） |
| 缺色条（某几条黑） | 单片机侧某条 lane 断 | `W` 看断在 12-19 / 20-27 / 32-39 哪段 |
| 花屏 / 雪花 | 单片机侧时序或中继不同步 | 换 `hstx_copy` 调试版逐段查 |
| **持续**撕裂闪烁 ✗ | 超出"变化触发"范畴 ⇒ 可能是单片机侧问题 | 记为不达标，继续查 |

## 5. 屏幕身份（本机实测，与两侧都无关）

- 台架那块屏 = `DISPLAY\KTC2154`「W21.5HDMI」(2009, EDID 1.3)：首选 1920x1080@60（148.5MHz），另有 1360x768@60；USB 侧 = 触摸 + 供应商 HID ✓
