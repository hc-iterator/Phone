## 一、已经定下的硬件决策（画板时的硬约束，不许自行改）

> 本节是**全文的硬约束总表**，每条都指到下面的详细条文（【用户定】标记）。
> **画图时照着做。** 原 `打板指南.md` §一 的内容与之重复，已于 2026-10-02 合并到这里。

### 1.1 显示与触摸

```
RP2350B ──HSTX(TMDS)──> HDMI ──> RTD2660H（在自打板上）──LVDS/TTL──> FPC ──> 裸屏
                                    ├── 背光驱动 ──> FPC ──> 背光 LED
                                    └── 触摸 ──I²C──> RP2350
```

- **所有芯片都在自打板上**，含 RTD2660H；裸屏用 **FPC 软排线**；**HDMI 不能省**
- **HSTX = GPIO12–19**（硅片硬连，阶段 2 走这里）；四层板、**100 Ω 差分对、等长**
- 触摸**不走"单片机转 USB"**，RP2350 直接读 —— ⚠️ 但**电容屏不能用 ADC 读**，总线是 **I²C（或 SPI）**
- **RTD2660H 的功耗必须进预算**：**3.3V / 317 mA + 1.8V / 578 mA**（重载条件）

### 1.2 电源与输入

| 项 | 决定 |
|---|---|
| 1.8V 来源 | **5V → 1.8V 直接 DC-DC**（**不走** 3.3V 再转 1.8V）；主供 RTD2660H，顺带 PSRAM+Flash |
| 为什么不用 LDO | 3.3V→1.8V 用 LDO 要耗散 **0.87 W**（SOT-23 温升 ~190 °C，不行） |
| 输入口 | **两个 Type-C 口**（方案 C，2026-09-29 定）—— ⚠️ **2026-10-01 重新权衡、未定**：与"PD 诱骗器 + 降压器"并列 |
| OR-ing 器件 | **大功率肖特基一颗**（用户定）；**绝不并联肖特基**（Vf 负温度系数 ⇒ 越热越抢） |
| 充电电流 | 调节电阻**必须可调**（THT 电阻位 / 多焊盘），**丝印标清"每个组合 = 多少 mA"** |
| 5V 峰值 | **约 2.5–3 A**（普通 USB 口给不出） |

### 1.3 存储与无线

- **QSPI CS0**：16 MB **1.8V** Flash
- **QSPI CS1**：16 MB **1.8V quad** PSRAM —— ⚠️ **必须 quad；octal OPI 不能用**
- **SDIO 4-bit + 板载 TF 卡座**（应用 `.bin` 从 SD 加载，**SD 是承重墙**）
- **无线 = CYW43439**（WiFi+蓝牙；**峰值 301 mA @ 3.3V**）
  - 走 **PIO 魔改 SPI**（**不占硬件 SPI**），但**占 1 个 PIO SM + 一段指令空间**
  - ⚠️ **它的几根线必须在同一个 PIO GPIO 窗口内**

### 1.4 调试触点（用户定，别省）

- 预留**主核 ↔ 副核互调**触点：**SWCLK / SWDIO / nRESET 三根**（GND 不占，同板共地）
- 两边**交叉对接**，每根**串 33–100 Ω**，**常开**；**同一组信号再引一组排针**给外部探针
- ⚠️ **动机就是"现在这块板够不着"**（SWD 一度不通、串口不枚举）—— 这块板是给"以后不再发生"买的保险

| | 阶段 1（现在） | 阶段 2（正式版） |

⚠️ **我 2026-09-29 在这里记错过一次**：记成"自打板上不放 RTD2660H"，
还据此推出"电源简化了、不用 1.8V 大电流"。**那是错的。**
⇒ RTD2660H 的 **3.3V 317 mA + 1.8V 578 mA**（datasheet 重载条件）**必须算进电源预算**。

**【用户定】触摸不走现成的"单片机转 USB"那条路，RP2350 直接读。**

⚠️ **但接口必须查清 —— 2026-09-29 核对结果：**

- **电容屏【不能】直接用 ADC 读。**
  电容触摸测的是 pF 级的互电容/自电容变化，必须由**专用控制器**去驱动 ITO 电极、
  做电荷积分再数字化。普通 ADC 做不到这件事。
  "哪怕是模拟信号也有 ADC"这条**只对电阻屏成立** —— 电阻屏本质是分压，ADC 确实能读。
- 常见 3.5" HDMI 屏的触摸控制器是 **I²C 接口**（FT6236 / GT911 / CST816 这一类）。
  板上那颗"转 USB 的单片机"很可能就是个 **I²C → USB HID 的桥**。
  ⇒ **"直接读"的方向是对的，但总线是 I²C（或 SPI），不是 ADC。**
- **待办**：查清屏上触摸控制器的**型号**，以及它挂在哪条总线上
  （板上有没有测试点 / FPC 能不能直接引出来）。

### RTD2660H 的其它输入方式（备选，**尚未决定**）

用户指出"这个解码芯片也不只有 HDMI 一种方式通信"。核对 datasheet 后确认，
它确实有这些入口 —— 但**能用性差别很大**：

| 方式 | 能不能用 | 说明 |
|---|---|---|
| **HDMI（TMDS）** | ✅ **已定用这条** | RP2350 走 HSTX |
| **8-bit ITU-R BT.656 数字视频输入** | ⚠️ **最有意思，但未验证** | RP2350 直接出标准清晰度数字视频，**完全不需要 TMDS/HSTX ⇒ Core1 解放**。代价：受 SD 视频制式（720×480/576 那档）限制，靠它内部的 scaler 缩到面板 |
| **外部 MCU 控制接口**（`si/mcu_sclk`+`so/scsb`，`ceb` 拉高选外部 MCU） | ⚠️ **理论可行，风险高** | 可以让 RP2350 当它的主控、不必给它烧固件。但 **Realtek 的寄存器手册不公开**，等于逆向 |
| VGA / AV / 分量（**模拟**） | ❌ **本方案排除** | **RP2350 没有 DAC**，发不出模拟信号 |
### 为什么本板这么别扭

- RP2350 的 **HSTX 硬连 GPIO12..19**，而 PiZero 的 40pin 排针占用了 GPIO0..27
  ⇒ DVI 只能挪到 GPIO32..39 ⇒ **只能 PIO bitbang** ⇒ Core1 被软件 TMDS 编码永久占用
- 这也就是**必须自己打板**的技术理由之一

### ⚠️ 布局硬约束：PIO 的引脚窗口二选一（2026-09-29 查实，**画板前必须知道**）

> **SDK 原话**：*On RP2350B, there are 48 pins but **each PIO instance can only address 32 pins**
> (the PIO instance either addresses **pins 0-31 or 16-47** based on `pio_set_gpio_base`).*

**⇒ 每块 PIO 的引脚窗口只有两种:`0–31` 或 `16–47`,不是任意滑动。**

**对我们的直接后果：**

| 用途 | 引脚 | 逼出的窗口 |
|---|---|---|
| **阶段 1 的 DVI（PIO bitbang）** | **GPIO32–39** | 🔒 **只能是 `16–47`** |
| **CYW43439 的几条线** | 待定 | ⚠️ **必须也落进 `16–47`**，否则**永远不能和 DVI 共用一块 PIO** —— 无论指令多短 |

**⇒ 画原理图时，无线的引脚要故意安排在 `16–47` 里**（除非那时已经改用 HSTX、不再需要 PIO DVI）。

> 补充：**阶段 2 用 HSTX，显示不再占 PIO**（HSTX 是硅片上的硬件），
> 所以这条约束主要影响**阶段 1**；但**副核 / 其它 PIO 外设**仍受它约束。

### 自打板要点

- RP2350B；**HSTX（GPIO12–19）→ HDMI/DVI**，四层板、100Ω 差分、等长
- **SDIO 4 位全速 + 板载卡座**（应用是 `.bin` 从 SD 加载，**SD 是承重墙**）
- 16MB **1.8V** QSPI flash + 16MB **1.8V quad** PSRAM 共用 QSPI ⇒ **两个都得 1.8V**
- ~~1.8V LDO 从 3V3 生成~~　⚠️ **已作废（2026-10-01 用户定）**
  ⇒ 改走 **5V → 1.8V 直接 DC-DC**。理由：**RTD2660H 对 1.8V 的消耗太大**（重载 **578 mA**），
  LDO 要耗散 **0.87 W**（SOT-23 温升 ~190 °C，不可行），而且 1.8V 是主负载所在的那一轨。
  定论见下方「阶段 2 电源架构」。
- ~~外部射频模块（ESP32-C3/C6 优先；RM2 不好买）~~　⚠️ **已作废**
  （2026-09-29 用户澄清：**从来只有 CYW43439 的 WiFi + 蓝牙，没有独立射频规划**）
- **无线 = CYW43439（WiFi + 蓝牙）**，峰值 **301 mA @ 3.3V**（datasheet 实测值，见 `docs/硬件设计.md`）
  ⚠️ **已查证（2026-09-29，SDK 源码）**：它**不是**走硬件 SPI，而是走
  **PIO 实现的"魔改 SPI"**（`pico_cyw43_driver/cyw43_bus_pio_spi.c` + `.pio`，
  用 `pio_claim_free_sm_and_add_program_for_gpio_range()`）
  ⇒ **不占硬件 SPI**（PL022 两个实例都还在）✓
  ⇒ **但它占「PIO 的 1 个状态机 + 一段指令空间」** —— 资源表该扣的是这两样。
  ⚠️ **布局约束**：它的几根线要落在**同一个 PIO GPIO 窗口**内
  （源码注释："The pins should all work in the same gpio base"）。
- 选型硬条件：**必须 quad（4 位）接口**；很多快的 1.8V PSRAM 是 octal OPI，**不能用**
- 1.8V flash 比 1.8V PSRAM **更难买**（本板现在用的是 W25Q128**JV**SIQ = 3.3V）——
  **画原理图之前先查两个的库存**

### PSRAM 片选分压（唯一跨电压域的信号线）

- **R1 = 680Ω（上）/ R2 = 560Ω（下）**
- 结果：2.66 mA、输出 **1.49 V**、戴维南 307Ω、0603 上 8.8 mW
- 3V3 ±5% ⇒ 1.416–1.565 V，仍在 VIH(1.26V) 之上、1.8V 之下
- **为什么走 1.5V 而不是 1.8V**：CMOS 输入有到自身 VDD 的 ESD 钳位二极管，
  1.8V 目标 + 3V3 偏 5% ⇒ 1.89V ≈ VDD+0.09V，会把钳位二极管正偏进 1.8V 轨
- 备选：用 1.8V 供电的单门缓冲器（同成本，零静态电流）
- 边沿慢时应该**在软件里调驱动强度**，而不是换小电阻

### 阶段 2 电源架构（用户 2026-09-29 定）

- **5V → 1.8V 直接 DC-DC**（**不走** 3.3V 再转 1.8V）。
  主供 **RTD2660H**（约 **578 mA**），顺带跑 **PSRAM + Flash**。
  **理由**：1.8V 负载大 —— 3.3V→1.8V 用 LDO 要耗散 **0.87 W**（SOT-23 温升约 190°C，不行）；
  5V→1.8V 走开关，效率高、发热小。
- **触摸不再绕 USB**：直接连屏的**触摸读取芯片**，接口大概是 **I²C 或 UART**。

#### 这套方案要注意的四条（我提的，非用户定）

1. **上电时序**：RTD2660H 是 1.8V 核心 + 3.3V IO 的多轨芯片。
   若 3.3V 先起来，IO 会往没上电的核心里灌电流（走 ESD 钳位），有**闩锁风险**（datasheet 提到 latch-up 100 mA）。
   ⇒ 要么查 datasheet 的时序要求，要么加 EN/电源良好链。
2. **5V 输入电流要重算**：1.8V 那路（578 mA）+ 3.3V 那路（RTD2660H 317 mA + 无线 301 mA + 卡/主控）
   + 背光。**5V 侧可能要 2.5~3 A** ⇒ ⚠️ **普通 USB 口给不出来**，得考虑 USB-C 取电或电池。
3. **1.8V 是共用轨，但 `adc_vdd` 是模拟 ADC 供电、怕噪声**。
   同一颗 buck 上还挂着数字负载（PSRAM/Flash）。
   ⇒ buck 的开关节点要远离 ADC 引脚，模拟轨加磁珠/LC + 去耦。
   若噪声真出问题，备选：buck 出 ~2.1V，再用小 LDO 给 `adc_vdd` 和 PSRAM/Flash。
4. **白赚的简化**：如果整组 QSPI（含 RP2350 的 `QSPI_IOVDD` 和 PSRAM 那颗 CS GPIO 所在的 bank）
   **都跑 1.8V**，那么之前为"3.3V 主控驱动 1.8V PSRAM"设计的**分压电阻就完全不需要了**。
   —— 这笔省下来的成本和信号风险不小，值得专门确认一下 bank 电压。

### 电池路线（**2026-10-01 用户提出，未定**）

> **用户原话（演变史）：**
> **"电池原来甚至前身是 5V 法拉电容用作断电保存的"** ——
> 那个电容的用途是 **"5V 断开后帮助 MCU 保存数据，然后来个 1KΩ 电阻放光电得了"**。
> **"但是现在这条路凑齐天时地利人和从羊肠小径变成丝绸之路了，方案自然落后几个八拍。"**

⇒ **电池从"窄用途的掉电保持"升级成了"整个电源架构的承重墙"**，所以旧方案（法拉电容）不够用了。

#### 为什么法拉电容在这个用途上确实不够

| | 法拉电容 | 锂电池 |
|---|---|---|
| **自放电** | **每天百分之几**（漏电流大） | 每月百分之几 |
| 能量密度 | 极低（只够毫秒~秒级） | 高 |
| 适合 | **短时掉电保持**（换电池、瞬断） | 长时间供电 |

⇒ 用超级电容做"掉电保存"**放几天就没了**。**用户的判断是对的**：想真保存要么换锂电，
**要么别靠电保存** —— 而本项目本来就走后者（见下）。

#### ⚠️ 但电池对本项目的**真正价值不是"保存现场"**

项目抗断电的路子是**快速启动 + 按需加载**，不是硬件保现场：
内核保持最小（MSP/内核栈在 SRAM）、应用 `.bin` 从 SD 按需加载、目标**内核到能显示 < 1 s**。
⇒ **电池的价值是两个**：
1. **脱线使用**（否则"手机"得插着线用，形态不成立）；
2. **解决峰值电流**（见下条）。

#### ⭐ 它一次解掉了两处未定项（这是最大的收益）

| 之前纠结 | 加电池后 |
|---|---|
| 两个 C 口凑 2.5–3 A | **不需要** —— 一个口充电就够 |
| PD 退回 5V ⇒ 屏 5V 轨欠压（~4.5V） | **消失** —— 5V 主轨由电池升压产生，与输入无关 |
| OR-ing / 双口保护 / 4 个 CC 下拉 | **全都不需要** |

⇒ **"谁家手机两个口的啊"的答案可能不是"忍两个口"，而是"根本不该从口取电"。**

#### 要定什么（顺序不能反）

```
电池容量 + 放电倍率        ← 先定这个
   ↓ 决定
充电电流（要多快充、能不能快充）
   ↓ 决定
充电 IC 型号（线性 or 开关、外围电感大小）
   ↓ 决定
5V 升压功率等级
   ↓ 决定
板子面积、发热、成本
```

**先定电池，别的才定得下来**；反过来先选充电 IC 会反复推翻。

#### 难点（"难搞"的具体内容）

| 新增模块 | 硬约束 |
|---|---|
| **充电 IC** | 要设**两个电流**（电池充电 + 输入限流 ILIM/DPM）；**线性充电 1 A 就耗散 1.3 W** ⇒ 走快充大电流**必须开关充电**（buck 型） |
| **保护** | 过充 / 过放 / 过流 / **温度（NTC）** —— 安全事，不能省 |
| **电池 → 5V 升压** | 同步升压 + 大电流电感；>2 A 发热可观 |
| **电量计** | ADC 分压测电压不准；要准得上专用 IC |
| **待机功耗** | "手机"要能待机，整机静态电流要控（影响升压 IC 选型与 EN 逻辑） |
| **形状 / 外壳** | 电池形状直接约束板形与 3D 打印外壳 |
| **安全** | 软包锂电要防穿刺/挤压，外壳结构要配合 |

#### 一个顺带的好处

手机工况是**间歇重载 + 长时间空闲**，大电池正好吃这个特性；**充电时系统可以不吃电**
（电池供着）⇒ **热设计反而比"边充边用抢电流"简单**。

> **待拍板**：上不上电池。它会影响**板形、外壳、成本、安全**，是架构级决策。

### 输入口与充电（用户 2026-09-29 定）

- **输入口用 Type-C。**
- **电池充电管理芯片的"充电电流调节电阻"必须可调**：
  做成**直插（THT）**电阻位，或者**把多个电阻做成多个触点/焊盘**，方便随时改配置。

#### 配套要注意的（我提的）

1. **Type-C 做受电端，必须 CC1/CC2 各接一个 5.1kΩ 下拉（Rd）。**
   漏了的话，用 **C-to-C 线**接充电器很可能**一点电都取不到** ——
   因为源端靠 CC 上的 Rd 才判断"有人在受电"，否则根本不输出。
2. **5V/3A 是非 PD 的 Type-C 上限，而本机峰值就要 ~2.5~3A。**
   ⇒ **边充边用可能根本充不进去。**
   两个出路：① 加 **PD 受电芯片**去谈 9V/12V（后级电流直接减半，buck 也更省）；
   ② 接受"用的时候基本不充"。
3. **多数充电芯片有两个电流要设**：**电池充电电流** + **输入限流（ILIM/DPM）**。
   只调前者不够 —— 输入限流设错会**把 5V 源拉垮**（尤其和系统负载抢电流时）。
4. **充电电流也是热设计旋钮**：线性充电器耗散 =(5V−3.7V)×I。
   1A 就是 **1.3 W**，SOT-23 上很烫。所以"能调"这件事同时也是"必须调"。

**建议做法**：留一个 THT 电阻位（轴向 0.25W，方便换）+ 旁边一组跳线/焊盘做粗调，
**丝印上直接标清"每个组合 = 多少 mA"**。

### PD 取电（用户 2026-09-29 定）

- **加 PD 诱骗器（受电控制器），谈 9V。**
  理由：**5V/3A 并非所有 Type-C 口都支持**，靠 5V 取电不保险。
- ⚠️ **附带结论**：一旦用上 PD 控制器，**CC 就由它接管**，
  之前说的那两个 **5.1kΩ 下拉（Rd）就不需要了** —— 两者二选一，别同时上。

#### 配套要注意的（我提的）

1. **下游必须能吃 5V ~ 9V 全范围。**
   源不支持 PD（或 PD 合同被撤回）时会**退回 5V**。
   ⇒ 如果 5V 那一路是 `9V→5V` 的**降压**，退回 5V 时它会掉到 ~4.5V（buck 没有升压能力），
   **屏的 5V 轨就欠压了**。
   ⇒ 要么那一级用**升降压（buck-boost）**，要么确认屏能容忍 ~4.5V。
2. **9V 侧电流账**：5V 侧峰值 ~2.5~3A ⇒ 换到 9V 约 **1.5~1.7A**
   ⇒ **PD 9V/2A（18W）就够**，不用追求 3A。
3. **保护**：VBUS 加 **TVS + 大容量电解/钽 + 电子保险丝或负载开关**（PD 热插拔会有浪涌）。
4. **拓扑两条路**：
   - ① `9V → 5V`（屏/背光），再由 **5V 分出 3.3V 和 1.8V** —— 省 buck，但串级效率低一点
   - ② `9V` 各自出 **5V / 3.3V / 1.8V** —— 三颗 buck，效率高、互相干扰小
5. **常见 PD 受电芯片**（去立创核对封装与存货）：
   `CH224K`（WCH，SOP-8，国内最常用、最便宜）/
   `HUSB238`（Hynetek，电阻或 I²C 配置）/
   `IP2721`（英集芯）/
   `FUSB302`（onsemi，只是 PHY，需要 MCU 跑 PD 协议栈，最灵活也最费事）

## 「两个 C 口」与「PD 诱骗器 + 降压器」两方案对照（⚠️ **未定，待用户拍板**）

> **用户 2026-10-01 原话：**
> **"2 个 C 口和 PD 诱骗器 + 主 DC-DC 输入（9V/12V/15V/20V，未定）（转 5V）降压器
> 的这两个方案各有千秋，未定。2 个 C 口简单粗暴，但是谁家手机两个口的啊？
> 2 号方案得考虑面积发热成本，难啊！"**
>
> ⇒ 两个候选并列，**下面保留各自的历史讨论**（2026-09-29 曾定方案 C，2026-10-01 重新权衡）。

### 方案 A：两个 Type-C 口（2026-09-29 曾定）

**取电方案的三选一（历史）**：~~A. PD 诱骗器 + 9V→5V 降压~~ / ~~B. 强行要求 5V/3A 输入~~ /
**✅ C. 做两个 USB 输入口**（两个口数据接线完全一样，并联取电，电流翻倍）。

⚠️ **但 2026-10-01 用户重新权衡后，这条不再算"已定"** —— 因为它有明显代价：

| 优点 | 代价（用户 2026-10-01） |
|---|---|
| 零协商逻辑、**任何充电头都能用** | **形态不合理**——用户原话：**"谁家手机两个口的啊？"** |
| 不存在 PD 协商失败 | 两个口都要 CC 处理（不做 PD 就是 **4 个 5.1k 下拉**） |
| — | 两个口都要 OR-ing（肖特基或理想二极管），**每个口一套保护**（TVS + 体电容） |

**不选"强行要求 5V/3A"的理由（用户判断，正确）**：5V/3A 并非所有 Type-C 口都支持，靠它不保险。

### 方案 B：PD 诱骗器 + 主 DC-DC 降压器（**2026-10-01 用户新提，未定**）

**做法**：加 PD 诱骗器（受电控制器）先谈高压，再经**主 DC-DC 输入降压器**降到 5V 主轨。
**输入档位：`9V / 12V / 15V / 20V` —— 用户标了"未定"。**

| 优点 | 代价（用户 2026-10-01） |
|---|---|
| **形态正常** —— 单口，"一个 PD 口走天下" | **面积**：多一颗 PD 控制器 + 一级降压（电感 + 多颗电容） |
| 一个 PD 充电头就能带满负载 | **发热**：多一级开关损耗；且**要算器件叠加**（9V→5V + 5V→3.3V + 5V→1.8V） |
| 高压传输 ⇒ 线损小 | **成本**：比两个 C 口多两颗 IC 量级 |

**必须先算清的三件事**（用户原话点出的"难"就在这里）：

1. **⚠️ 退回 5V 的欠压陷阱（最关键）**：PD 合同被撤回 / 源不支持 PD 时会**退回 5V**。
   若那级是 `9V→5V` 的**降压器**，它会掉到 **~4.5V**（buck 没有升压能力）⇒ **屏的 5V 轨欠压**。
   ⇒ 要么那一级用 **buck-boost（升降压）**，要么确认屏能容忍 ~4.5V。
2. **面积账**：PD 控制器 + 电感 + 输出电容占多少板面？**板上还有 RTD2660H、CYW43439、
   SD 卡座、HDMI 座、FPC 座** —— 面积本就是紧张资源。
3. **发热账**：沿链路逐级算损耗，注意**热叠加**（不是单颗的温度，是它们凑在一起的温升）。

**输入档位为什么"未定"是合理的**：`9V/2A` 与 `12V/1.5A` 都是 18 W，但**档位越高 ⇒ 后级压差越大**；
而且**不是所有 PD 源都支持全部档位**（尤其 15V/20V）⇒ 选档位时要对着 `CH224K` 之类诱骗器的
支持列表，以及常见充电头的实际输出能力来定（2026-09-29 曾算过：`9V/2A` 就够）。

#### ⚠️ 但"两个口直接并联就是双倍电流"不成立 —— 三个前提

1. **绝对不能直接并联，必须做 OR-ing（理想二极管 / 电源多路复用）。**
   直接并的后果：
   - 电压高的那一路会**倒灌进另一路** —— 如果另一头是**电脑的 USB 口**，这是不允许的；
   - 如果其中一路是 **PD 的 9V**，直接并在 5V 上会**烧东西**。
   ⇒ 两个口各自经 OR-ing 再汇到 5V 轨。
2. **"双倍"是指"两个口各自能力的和"，不是保证 3A。**
   两个**电脑 USB3 口** ≈ 2×0.9A = 1.8A（不够）；
   两个 **5V/2A 充电头** = 4A（够）。⇒ **靠的是充电头，不是电脑口。**
3. **每个 C 口各自都要 CC 处理**：不做 PD 的话，**每个口 CC1/CC2 各一个 5.1k 下拉（4 个电阻）**；
   做 PD 的口则由 PD 控制器接管 CC。

#### 如果以后想同时支持 PD（推荐做法）

**别把 9V 和 5V 在同一个 OR 节点上并。** 正确顺序是**先降压、再汇合**：

```
口 A（C，带 PD）──> PD 控制器 ──> 9V ──> buck ──> 5V ──┐
                                                        ├── OR-ing ──> 5V 主轨
口 B（C，普通 5V）────────────────────────> 5V ─────────┘
```

这样：**单独一个 PD 充电头就能带满负载**；两个普通充电头也照样能用。

#### OR-ing 怎么实现

| 做法 | 代价 |
|---|---|
| 肖特基二极管 | 最便宜，但 3A 时压降 ~0.45V ⇒ **1.35W 发热**，要选大封装（SMA/SMB） |
| **理想二极管 / 电源多路复用 IC**（首选） | 压降几乎为零，发热小；候选：TI `TPS2121`、`LTC4412` 一类（去立创核对参数） |

> ⚠️ **现实取舍**：手机上插两根线其实挺别扭，优雅解是"一个 PD 口走天下"。
> 但两个口的**好处是零协商逻辑、任何充电头都能用** —— 对"技术验证"阶段是合理的保守选择。

### OR-ing 定为"大功率肖特基"（用户 2026-09-29 定）

用户判断：**5V 上的压降损耗问题不大，上大功率肖特基就够了。**

#### 三条落地细节（我提的）

1. **绝对不要把肖特基并联来分摊电流。**
   肖特基的 Vf 是**负温度系数** ⇒ 热的那颗会抢走更多电流 ⇒ **越热越抢，正反馈**。
   ⇒ 选**一颗**额定够大的，不要"两颗小的并起来"。
2. **按热来选封装，不是按电流标称值。**
   3A 时 Vf ≈ 0.45V ⇒ 耗散 **~1.35W**。
   `SMA`（θJA≈75°C/W）温升会到 ~110°C，**偏危险**；
   ⇒ 用 **DPAK / SMC / 直插(DO-201AD)**，并给足铺铜散热。
   候选（去立创核对）：`MBRD340`(DPAK) / `SS54`(SMB) / `SB540`(直插) /
   低 Vf 的 `PMEG4050`(Nexperia)。
3. **白赚的将来升级路径**：把那个位置的**封装同时做成能装 DPAK 肖特基、也能装 DPAK P-MOS**
   ⇒ 将来若发现发热不可接受，**直接换件成"理想二极管"，不用重新打板**。

**每个输入口各一套**：一颗肖特基 + 一颗 TVS + 一个体电容。


### 调试触点：主核 ↔ 副核 互调（用户 2026-09-29 定）

**【用户定】预留一个触点，专门用于调试：触点接上后，主核可以调试副核，
或副核可以调试主核。**

#### 动机（这条是对症下药）

**现在这块板子就卡在"够不着"上** —— SWD 链路断了、串口枚举不了，
板子跑着会重启的固件，**没有任何手段能进去**。
自打板上留这个触点，就是为了**以后不再出现这种情况**。

#### 规格（我补的）

| 项 | 内容 |
|---|---|
| **需要几根** | **SWCLK / SWDIO / nRESET —— 3 根**。<br>**GND 不用占触点**：**同一块 PCB 上本来就共地** |
| **为什么要有 nRESET** | 板子跑飞/砖掉时，靠它把核钉住才能接管 |
| **接法** | 两边的 SWD 信号**交叉对接**（A 的 SWCLK ↔ B 的 SWCLK…），中间过触点 |
| **串阻** | 建议每根串 **33~100Ω**，限制两端同时驱动时的争用电流 |
| **常态** | **常开**。不接的时候两边互不影响 |
| **白赚的一条** | 同一组信号**再引一组排针**给外部探针 —— 成本≈0，但多一条后路 |

#### ⚠️ 一个实际限制要知道

**谁当探针，谁就得烧探针固件。**

- 让**副核当探针**去调主核 ⇒ 副核**此时跑不了应用固件**（它在跑 debugprobe）；
- 反之亦然。
- ⇒ 在 **bring-up / 救砖阶段完全可以接受**（那时本来也不需要副核干活）；
  但**不能指望"边跑应用边互调"**。

#### 还要注意

- **SWD 用的引脚必须留干净**，别被别的功能占掉
  （本板就是引脚被 40pin 和 DVI 占光才这么难受）；
- 触点在**丝印上标清楚**，并在原理图里画成一个明确的可选连接；
- **触点位置要方便够得着**（不用拆机）。

## 二、引脚规划（画图时最容易定错、定错就废）

> **详细条文见本文件「布局硬约束：PIO 的引脚窗口二选一」与「自打板要点」。这里只留决策要点。**

### 2.1 🔴 最硬的一条：PIO 引脚窗口二选一

> **SDK 原话**：RP2350B 有 48 脚，但**每个 PIO 实例只能寻址 32 脚**，
> 且**只能是 `0–31` 或 `16–47`**（按 `pio_set_gpio_base`）。
> ⇒ **同块 PIO 的两个程序，引脚必须落在同一个窗口里，否则永远不能共用一块 PIO。**

**对阶段 2 的影响**：阶段 2 用 **HSTX**，**显示不再占 PIO**，
所以这条**主要影响仍用 PIO 的外设**（CYW43439、以及任何 PIO 外设）。
但**画板时仍要故意把无线那几根线安排进同一个窗口**——否则以后没有退路。

### 2.2 已占/已知的引脚（阶段 2）

| 用途 | 引脚 | 来源 |
|---|---|---|
| **HSTX（HDMI 出）** | **GPIO12–19** | 硅片硬连 |
| QSPI Flash（CS0） | 由 RP2350 固定 QSPI 脚 | 芯片固定 |
| QSPI PSRAM（CS1） | 同上 + **一个 CS** | 若与 Flash 同跑 1.8V |
| SDIO 4-bit | D0–D3 必须**连续**，CLK 由驱动推导 | `src/hw_config.cpp` 的公式 |
| CYW43439 | **待定**（必须同 PIO 窗口） | 「布局硬约束」一节 |
| 触摸 | **待定**（I²C/SPI） | 待查 |
| SWD 触点 | SWCLK / SWDIO / nRESET | 「调试触点：主核 ↔ 副核 互调」一节 |

### 2.3 ⭐ 一个能省成本的机会

实测 PIO 用量：**DVI 4 条 + 无线 5 条 = 9 条** ⇒ **DVI 和无线可以共用一块 PIO**，省下一整块。
阶段 2 改用 HSTX 后，**整个项目可能只占 2 块 PIO**（见 `资源表.md`「PIO 的正确记账单位」）。

## 三、电源预算（打板前必须重算一遍）

### 3.1 已知的负载（数字对得上出处）

| 轨 | 负载 | 电流 |
|---|---|---|
| **3.3V** | RTD2660H | **317 mA** |
| 3.3V | CYW43439（峰值） | **301 mA** |
| 3.3V | 卡 / 主控 / 其它 | 待估 |
| **1.8V** | RTD2660H | **578 mA** |
| 1.8V | PSRAM + Flash | 待估 |
| 5V | 背光 | **待查**（取决于屏） |

⇒ **5V 侧峰值可能 2.5–3 A**（本文件「阶段 2 电源架构」一节）。

### 3.2 ⚠️ 必须先确认的一件事：整组 QSPI 是否都跑 1.8V

> 如果 **QSPI_IOVDD 和 PSRAM CS 所在的 bank 都跑 1.8V**，
> 那么原先为"3.3V 主控驱动 1.8V PSRAM"设计的**分压电阻（R1=680Ω / R2=560Ω）就完全不需要了**
> —— 省成本、还省掉唯一的跨电压域信号线。（本文件「阶段 2 电源架构」四条之第 4 条）

### 3.3 四条硬注意（都是事故预防）

1. **上电时序**：RTD2660H 是 1.8V 核 + 3.3V IO。**若 3.3V 先起，IO 会经 ESD 钳位往未上电核心灌电流**
   ⇒ 有**闩锁风险**（datasheet 提 latch-up 100 mA）。要么查时序要求，要么加 EN/电源良好链。
2. **`adc_vdd` 怕噪声**：1.8V 是数字/模拟共用轨 ⇒ buck 开关节点**远离 ADC 引脚**，模拟轨加磁珠/LC + 去耦。
3. **PD 下游要吃 5–9V 全范围**：PD 合同被撤回会退回 5V；若那级是 `9V→5V` 降压，
   会掉到 ~4.5V ⇒ **屏的 5V 轨欠压**。要么用 buck-boost，要么确认屏能容忍。
4. **无卡检测脚**：板上 TF 座**没接卡检测**（`use_card_detect = false`）——
   阶段 2 要不要加？加了要占一个 GPIO。

## 六、软件侧可以同时推进的（不必等板子）

打板是硬件线，**软件线不必停**。下面这些**不依赖打板**：

| 能做的 | 为什么现在做 |
|---|---|
| **BSP 板级支持层** | 规范要求；阶段 2 硬件不同，**没有 BSP 所有引脚要重写** |
| **应用加载器 + 内存假磁盘** | `docs/当前状态.md` 里明确列的下一步；**不必等真 SD** |
| **HSTX 显示后端** | 阶段 2 的显示路径，可在阶段 1 板子上先写（引脚不同但逻辑通用） |

> ⚠️ **但有一条底线**：这些改动**上机验证很有限**（见 `docs/当前状态.md`），
> 所以**打完板第一次上电时，要预料到"主机侧全绿的东西可能有硬件假设错误"**。
