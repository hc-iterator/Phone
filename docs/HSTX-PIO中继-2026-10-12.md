# HSTX + 两级 PIO 中继：把 12-19 送到 HDMI 座 32-39（2026-10-12）

## 结论（先说结果）

- **HSTX 硬连 GPIO12-19**：SDK 的 `FUNCSEL_VALUE_HSTX_0..7` 只定义在这 8 个脚上，别的脚连这个功能选项都没有；GPIO 的"输出覆盖"也只有 {外设/反相/强0/强1}，没有跨脚路由。
- **HDMI 座在 GPIO32-39**（用户查原理图确认，板上焊死、不可改）。
- **一个 PIO 实例的窗口只能是 0-31 或 16-47**：`PINCTRL` 的 `IN_BASE[19:15] / OUT_BASE[4:0] / SET_BASE[9:5] / SIDESET_BASE[14:10]` 全是 5 位，且都相对**实例级** `PIO_GPIOBASE`（该寄存器只有 bit4 一位 ⇒ 只能 0 或 16）。
  ⇒ **单个 PIO 实例不可能"读 12-19 同时写 32-39"**。
  实测佐证：base=0 时把 `out_base` 写成 32..38 会被截成 0/2/4/6 —— **这正是 1 号系统当初黑屏的原因**（信号其实跑到 GPIO0/2/4/6 上去了，HDMI 座什么都没有）。
  顺带查实：那套 PIO DVI 引擎（frank_hdmi）**本来就设对了** base=16（`frank_serialiser.c:88`），所以它确实在驱动 32-39。

## 解法：两级窗口中继（用户提出，已实测通）

| 级 | 实例/基址 | SM 数 | 做什么 |
|---|---|---|---|
| 第一级 | PIO0 / base 0 | 4（每对差分线一个） | `IN=12/14/16/18 → OUT=20/22/24/26`，**顺带完成配对重排**（HSTX 顺序 CLK,D0,D1,D2 → HDMI 座顺序 D2,D1,D0,CLK） |
| 第二级 | PIO1 / base 16 | 1 | `IN=20 → OUT=32`，直通到 32-39 |

- 中间脚 **20-27**：既是 PIO0 的输出、又是 PIO1 的输入，**同一批 pad，不需要任何外部连线**。
  （PIO 能读到"不是自己驱动"的 pad —— 这条已由 HSTX→PIO 的复制实验独立证明。）
- 中间脚的选取约束：必须同时落在 PIO0 窗口(0-31) ∩ PIO1 窗口(16-47) = **16-31**，再避开 HSTX 占用的 16-19 与被占用的 28-31（1 号系统上是 SD 与 PIO-USB）⇒ 正好剩 **20-27**，两个系统都可用。
- 全程只有一条 `mov pins, pins`（`0xA000`）：1 指令/位、`clkdiv=1` ⇒ 252 M 次更新/秒 = **逐位同速**；无缓冲、无 DMA、无中断参与 ⇒ **无抖动**；四条 lane 经过的两级延迟完全相同 ⇒ **skew = 0**（这也是"16-19 明明能被 PIO1 直读、却仍要陪跑第一级"的原因：不等延迟就会差一个位周期 3.97 ns，TMDS 必崩）。

## 为什么别的路子不行

- **HSTX 换脚**：硅片硬连，不可改。
- **DMA 读 GPIO 寄存器搬**：`gpio_in → gpio_hi_out` 是合法通路（SIO 里 `gpio_in/gpio_hi_in` 与 `gpio_out/gpio_hi_out` 都在），但① 每次传输要读+写两个总线周期 ⇒ 速率只有所需的约一半；② `gpio_in` 的 bit12-19 要落到 `gpio_hi_out` 的 bit0-7 = **错 4 位移位**，DMA 只能字节/半字/字对齐搬；③ 总线仲裁导致传输完成时刻飘几十 ns，而 TMDS 靠边沿精度恢复时钟 ⇒ **三条都致命**。
- **IRQ 传数据**：PIO 的 IRQ 只有 8 个标志位，**没有**"把标志当数据读出来"的指令。

## 实测数据（2026-10-12）

- **连通性**：待测板把 GPIO0..20 逐脚拉高走一圈，观察板记到 `STICKY 0x01ffbff` ⇒ 21 根里只有 **GPIO10** 没通。用户复查后确认：**10 号那根杜邦线接到了地**，已修。
- **三级活动度**（20ms 内跳变数）：HSTX 12-19 ≈ 119728、中继1 20-27 ≈ 119319、中继2 32-39 ≈ 119926 ⇒ **32-39 确实在被驱动**。
- **逐位映射（硬数据）**：源 `src=0x56` 按配对重排应为
  `((0x56&3)<<6)|(((0x56>>2)&3)<<4)|(((0x56>>4)&3)<<2)|((0x56>>6)&3) = 0x95`，
  **输出实测正是 `0x95`** ⇒ 位映射与配对顺序完全正确。
- **`K` 全量对拍**：**尚未拿到可判定结果**。前几轮测的是台架自身的问题（① 我在运行时改 `clk_hstx` 没能真的改变串行器速率；② 采样 252 MSa/s = 1 GB/s 超出 DMA 能力 ⇒ FIFO 反压使两个采样 SM 各自不规则停顿、两路时间漂移）。已改为 **PIO 图案源 + 采样 `clkdiv=10`（25.2 MSa/s）**，待复测。

## 教训（都已入坑）

1. **改运行时时钟要传目标频率**：`clock_configure(clock, src, auxsrc, src_freq, freq)` 最后一个参数是 **Hz**，不是分频（传 `16.0f` ⇒ 实际只到 3845 Hz = 252M/65536）。
2. **PIO 的 SM 要按实例算**：`pio_claim_unused_sm(..., true)` 拿不到会 **panic** —— 中继第一级要 PIO0 全部 4 个 SM，别的功能占用同一实例就会炸。
3. **别把唯一的遥控复位手段刷掉**：采样板上带 `Z` 的固件一度被 `core1_monitor` 覆盖，导致待测板 panic 后无人能救。现在两个方向都有复位线（采样板 GPIO28→待测板 RUN、待测板 GPIO42→采样板 RUN）。
4. **252 MHz 超频必须带散热**（采样板就是因为没散热 + 连续大转储而卡死的）。
5. **本机 `Get-Volume` / `Get-CimInstance` 会静默返回空**：找 BOOTSEL 盘必须用 `Get-PSDrive -PSProvider FileSystem` 再 `Test-Path <盘>:\INFO_UF2.TXT`。
