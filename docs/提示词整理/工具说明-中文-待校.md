## status

汇报 PicoPhone 台架状态：受管路径、工具链版本、git 分支/头提交/脏状态、VID 为 2E8A 的 USB 设备、持有 rig lock 的对象、闪存台账中的最近镜像、以及卡死的调试进程。只读；在文本旁以 json 对象同步返回相同事实，便于两次运行做机械对比。

## github

通过本机加速器从 GitHub 抓取 URL。hosts 文件把 github.com、api.github.com 与 raw.githubusercontent.com 指向 127.0.0.1，由 Steam++.Accelerator 终结 TLS 并转发；这会导致 web_fetch（非公网 IP）与普通 TLS 客户端（无其证书吊销列表）失效。本工具直接与该加速器通信，返回状态行与响应体。可传完整 URL、以 `/` 开头的 API 路径（如 `/rate_limit`）、或 `owner/repo` 形式。

## gui_windows

列出 Agent 可观测的顶层窗口：句柄、进程、尺寸与屏幕位置、标题、最小化标志。这是 Agent 获知窗口存在的唯一途径 —— 它永远不会收到全屏截图。传 `all: true` 可包含隐藏的辅助窗口（噪声大；仅供调试）。

## gui_capture

按句柄截取单个窗口并保存为 PNG，返回文件路径。使用带 PW_RENDERFULLCONTENT 的 PrintWindow，因此被遮挡的窗口仍能返回自身内容（最小化、受 DRM 保护、独占全屏的窗口返回黑帧）。优于任意全屏截图：Agent 只会看到它指名的那个窗口。

## gui_zoom

放大镜：给定一个屏幕坐标点，返回一张以该点为中心的小图（默认 100x100 原生分辨率），带红色十字准星，以及把图像映射回绝对坐标的 `origin`。当 Agent 能看到某物却读不清时使用 —— 它永远不必盲目猜坐标。

## gui_launch

启动一个程序并将其窗口放置到虚拟显示器上，使用户看不到它。使用 SetWindowPos 并带有 SWP_NOACTIVATE：不会窃取焦点。优先使用此工具，而不是自行启动程序，否则窗口会出现在用户的主屏幕上。

## gui_place

将一个窗口移动到虚拟显示器（或指定坐标）上，但不激活它。当窗口由其他程序启动且位于用户屏幕上时使用此工具。

## gui_vdd

管理 Parsec 虚拟显示器：`status`（设备和屏幕列表）、`add`（插入虚拟显示器）、`remove`（按索引拔出）。一个 keeper 进程每 50 ms 向驱动发送 ping；如果没有该进程，虚拟显示器会在大约 1 秒后被拔出。

## gui_browser

通过 CDP 与 Chromium 浏览器或 Electron 应用进行交互：`tree` 返回可点击元素的精确矩形、文本和 CSS 选择器；`click` 通过选择器触发真实点击；`type` 设置输入值；`list` 显示目标；`eval` 运行单个表达式。此工具不会移动真实鼠标，因此可在虚拟显示器上无焦点状态下工作。

## gui_uia

通过 UI Automation 读取或操作窗口。`tree` 返回每个控件的类型、名称、AutomationId 和精确矩形；`invoke` 通过 AutomationId 或名称触发控件，且不会移动鼠标或窃取焦点——优先于坐标点击。适用于 Win32/UWP/WPF 应用；Chromium 网页内容不暴露（请使用 gui_browser/CDP 代替）。

## gui_click

通过真实输入注入点击屏幕上的一个点。此操作会移动真实鼠标光标，并且要求目标窗口处于前台，因此会抢走焦点——仅在 gui_uia/gui_browser 无法操作时（画布、自绘 UI）使用。需与 gui_verify 配合使用。

## gui_verify

验证操作是否确实生效：先捕获窗口，再运行命令，之后再次捕获，并报告像素变化比例。会明确给出 changed/unchanged 判定——切勿假设点击已生效。窗口在前台时使用屏幕捕获（可避开 WinUI3 应用的陈旧帧问题）。

## build

用项目自有脚本构建，返回退出码、日志尾部、以及产物路径和时间戳。成功时还会在产物旁写入 build_info.txt（源提交、是否脏、工具链）；失败时返回前几条编译错误，而不是只给日志尾部。

## flash

把 uf2 写进板子并报告板子的回应。默认走 backdoor：通过串口请正在运行的固件进入 BOOTSEL。烧写会中断正在运行的应用，而这台台架上 BOOTSEL 按钮是唯一的恢复手段。写入前会核对已挂载 BOOTSEL 卷的身份是否与目标板一致、取台架锁，并在 debug_logs/flash_ledger.jsonl 里追加一条记录（镜像指纹、源提交、结果），以便事后回答“板上到底是哪份镜像”。

## serial

一次性读取 USB CDC 端口一段限定的时间并返回捕获文本。按 VID/PID 认板子，不按 COM 号（COM 号每次重插都会变）。打开端口约需 4.5 秒，因此需要多次读取或“发送后等待”时请用 pico_console。该工具会取台架锁，并发读取会直接报错而不是争抢端口。

## console

在多次调用之间保持一个串口打开，以便与设备进行交互式驱动。`open` 需要支付一次 4–5 秒的端口打开成本，之后 `send`、`read`、`expect` 就很便宜。需要按键驱动的固件时，请用这个工具而不是 pico_serial。`expect` 发送并等待，直到某一行匹配正则表达式，因此无需猜测睡眠时长；超时会明确指出没有匹配到任何内容。每行默认带墙钟时间戳，这使得“每 30 秒闪一下”这种行为可以被证明。台架锁在会话打开期间一直被持有，关闭会话或空闲超时后释放。

## temp

读写本会话 %TEMP% 目录下的文件。这是项目用来放抓包、负载与转储的临时工作区。路径被限制在 %TEMP% 内，无法逃逸。

## git

在主仓库或一个独立的 Agent 空间里运行 git 命令并返回其输出。会改变历史的动词（commit、push、reset、checkout、merge 等）必须设置 `mutate: true` 才被执行。

## run

运行仓库 `tools/` 目录或项目 `dsh-plugins/` 目录下的一个项目脚本（ps1、cmd、bat、py），返回退出码与输出。SWD 工具、进程守卫、Agent 空间脚本、文档门禁与遥测解析器都通过它调用。其它位置的脚本会被拒绝。

## exec

运行一个在白名单内的构建或调试可执行文件，返回退出码与输出。`~\.pico-sdk` 下的工具链目录（cmake、ninja、arm-none-eabi-*、picotool、openocd）以及 Visual Studio 的 vswhere/MSBuild 目录会被前置到 PATH，使这些命令可直接解析。shell 被刻意排除，`cl` 也被排除（它离不开 Visual Studio 开发环境）。项目脚本用 pico_run；MSVC 构建链用 pico_build host-test。
