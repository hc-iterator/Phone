### 7.1 显示芯片（纸 A 新增）

| 项 | 要求 |
|---|---|
| 芯片 | 支持输入 DVI/HDMI/DP；输出屏幕格式待定 |
| 分辨率 | **720P 60Hz+**（便于以后升级） |
| 功耗 | 总功耗**不超过 10W** |
| 评价维度 | **性能 / 功耗 / 成本** 三点 |
| 触摸 | 需一颗芯片解析电容屏，输出 I2C 等单片机可解析波形 |
| 背光 | 芯片与屏幕背光**一起考虑** |

### 7.2 三个想法（纸 A 新增）

1. **PIO 自动循环（最有价值）**：每 SM 必然有一个寄存器指向最后一条指令；**改它和地址寄存器让"现状 > 上限"会发生什么**？能否**省掉拼合时的 `jmp`**，省指令时间与空间 ⇒ 可能引向重大资源突破（**待验证**）
2. **PIO 代码包（纸 B）**：代码块 → 打包 → 代码包 → 编译 → 指令包；难点是**各功能到各 SM 的分配**；"少拼合又不降灵敏度"—— 神经网络上不起，只能手写 C++ 逻辑
3. **温补晶振（纸 A）**：给 Pico 用上让 Pico 自己计时；屏幕/主核/外设全关时副核也能计时

### 7.3 电 — 新增的只有电池部分（纸 B）

| 项 | 结论 |
|---|---|
| 深度睡眠 | 主核要能被唤醒不断电；1000mAh 待机几天即可 |
| 电池汇入 | 无电荷泵：主降压器升级成升降压器 / 直接给 3.3V+1.8V + 5V 升压器反向供电；有电荷泵：直接汇入主升降压器 |
| 电池充电 | 接入即使能的充电芯片；电流最好由 Pico **PWM 动态调**（I2C/SPI 资源也够） |

### 7.4 WindowsPico 的定位修正（纸 B 末尾）

**修正**：我之前判"不值得做"，漏了**没有硬件**这个前提。改为：

- ✅ **值得做**，定位是「**可完全掌控的软件模型 + 精确重做**」，不是"周期精确的硬件模拟器"
- ⚠️ 边界：PIO/DMA 的**周期精确**做不到 ⇒ 它缩小嫌疑范围，**不替代**上机验证
- 优先级：**无板子期间，它是唯一能推进的迭代路径**
