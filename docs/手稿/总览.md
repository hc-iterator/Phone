## 二、每张纸讲什么（一句话版）

### 2026-10-21

| 纸 | 内容 | 一句话 |
|---|---|---|
| **纸1** | 系统接口函数设计 | 六大模块（`command` / `math` / `memory` / `wifi·BLE·BT` / `Display` / `System Manage`）；命令行用 `namespace psc`，仿 cmd 但要权限判定；`addcmd` 用参数条件表注册；系统函数一律 `SM_` 前缀 |
| **纸2** | 工具链 | **Picocmd**（非 SWD 后门：串口读写寄存器/内存/断点/看门狗）、**WindowsPico**（PC 上模拟 Pico）、**SuperDebug**（统一调试路径自动路由）；外加重启接口收敛、工作区迁移、模块依赖 |
| **纸3** | 系统设计图 | C++ 为主；SRAM 要划 300KB 给显示 ⇒ 16MB Flash 做 XIP 启动区、16MB(也可能 8MB) PSRAM 做主内存、SD 卡当硬盘；框图四块（调试电路/主信号通路/电源/PIO）；**PIO 拼合公式**：`X1+…+Xn+n < 32` 才能合并；USB Hub 主从设计；DMA 由内核统一分配；蓝牙组网与同步 |

### 2026-10-22

| 区块 | 内容 | 一句话 |
|---|---|---|
| **工具与项目管理** | 2 个工具（① 随机数/哈希 ② 仅本对话可见的记录本）；工具各自独立 git、`.git` 加密、作者 Agent 审核；文档统一收 `/docs`；子 Agent 行为模式；根目录 `Readme.md` 写心思想与回答方法 |

## 五、三个最容易搞混的名字

| 名字 | 指什么 | 不是什么 |
|---|---|---|
| **纸条** | **你的手写稿本身** | 不是稿子里设想的"留在原处的通知文件" |
| `陷阱.md` 里的"纸条"机制 | 稿子里的**一个设想**（复制插件时留通知），**还没实现** | 不是手稿的别名 |
| `History\` | **会话日志**归档（`.jsonl`） | 不是手稿 |

## 六、维护规矩

1. 新拍手稿：建 `YYYY-MM-DD\` 目录 + `页NN.jpg`，走 `tools/manuscript/` 三步出 `纸N_成品.png`，写该目录 `README.md`，**然后回来更新本文 §一/§二/§三**。
2. 手稿里有新决策：先更新 §三 的状态，再动代码。
3. 手稿与代码冲突：**以手稿为准**，在 §三 标出冲突并报告。
4. 不要在本文件复制转录原文 —— 只做索引与状态，原文留在转录文件里。
