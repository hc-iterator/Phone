- 参数列表是记录「参数条件 + 参数」的表格。该表格两项中任一项都能为「字符串+占位符」——
  **template〔？〕**。
- `addcmd(std::function<…>, 参数列表, funcname)`：
  该输入列表包含了全部允许输入参数名称、为「特殊值」时则重构该位置允许无关参数存在。
- `std::string(""), ("r", 0), ("r", std::string(""))`：
  `std::string(""), ("r", 0), ("r", std::string(""))` → 33. `gpio`？
- `addcmd` 为抽象函数〔？〕，每一项参数都自动初始化，
  而无论如何重例化，均引用其复数多个对象存储。
- 此时就重构化出 `string, int, string`，以 `"r"` 为特殊值。
- 假设调用者未填号（`mode`），则 `command` 分导器不会
  在调用 `func` 时传回 `("r", 0, std::string(""))` 这

## 纸2·C Pico cmd（页03；页05 是这一张的全景）

### 1. `Pico cmd`

- `Pico cmd` 是一个子项目，目的是**非 SWD、非自调试**，实现串口读写寄存器、内存、Flash、缓存、
  打断点、做 BOOTSET、强制重启等功能。
- `Pico cmd` 为载荷提供以下函数：

1. **安全执行危险命令**
   调用此函数，`Pico cmd` 会将当前状态存盘，在下次 `main` 函数的第一行插入断点，然后设置看门狗，
   占据 Core1 持续喂狗。一旦 Core0 执行超繁忙操作造成死机，机器随即重启。
2. **软件断点**
   `Pico cmd` 的断点机制为：将某行指令改为跳转到断点函数的命令，并储存该行代码，在断点函数中恢复。
   断点函数也支持被载荷直接调用。
3. **协程 Core1 代码执行**
   `Pico cmd` 主代码也有一份协程版，载荷可以申请递交一个协程函数在 Core1 运行。
4. **串口支持**
   Core1 独占了串口，载荷需将 `printf` 等操作发给 `Pico cmd`，由它代为执行。
5. **PIO 重启**
   依靠主频 + 数数，PIO 也能作为定时唤醒 CPU。PIO 一来能作为看门狗失效的保险，二来能作为协程
   切换信号，同时处于高口〔？〕的控制范围内。

### 5. 逆向

- 新插件正在整合，也已有一些头绪。
- 为避免浪费大量 Token 对付汇编，`Pico cmd` 包含一个「电脑-转换」组件，将 Agent 所要和 Pico 通信的
  函数指针表转为函数名，将 Agent 修改的代码编译后发给 Pico 等。这座桥也同样架在 `Pico cmd` 和
  `SuperDebug` 之间。

- 插件会提供格栅化能力，Agent 可通过调整格子大小、经简单数格子快速确定想要的坐标。插件也提供
  虚拟鼠标，方便 Agent 确定某坐标对应的位置。

### E.3 PIO 拆解（页07/08 左栏）

- 给定：若 n 个代码段长度分别为 `X1, X2, …, Xn`
- 若 `X1 + X2 + … + Xn + n < 32`，则可拼合。`n` 代表 SM 指令。
- 即一个 PIO 模块可用 SM 自由选择哪个代码。
- 举例：

```
| 0 0xx | 1 0xx |
| 2 1xxx| 3 10xx|
```

- `X1=3, n=1`（代码1）；`X2=4, n=2`（代码2）
- 若起长为 0，则 = 代码1；若起长为 4，则 = 代码2。
- 很多函数用 SM 没有几个指令，如此即冗余例用 SM〔？〕。
- `jmp` 是找地址。
- `jmp` 指令会占用时间，需要对时序。
- 表：

```
| 7 1YY | 6 1YY |
| 5 YY  | 4 YY  |
| 3 jmp 0 | 2 1xxx |
| 1 xxx | 0 xx |
```
