3. `command` 注册

- `command` 的本质是一个表格，比方说 `std::vector`，其中的每一项都是一个**返回值为 `const char *` 的、
  输入为一个参数列表的函数**。〔图上在旁边标了 `template<?>`〕
- 参数列表是记录「(参数条件 + 参数)」的表格，该表格两项中任意一项都能为**特殊值**以指代万〔能〕。
- `addcmd(std::function<...>, 参数列表, funcname)`
  该输入列表包含了全部允许输入参数条件。为特殊值时，则意味着该位置允许无关参数存在。
- 例：

```
addcmd(std::function<…>, []{("r", std::string("")), ("r", 0), ("r", std::string(""))}, "gpio");
```

- `addcmd` 为抽象函数，每一项参数都自动实例化，而无论什么重例化，均可用其父类指针多态存储。
  此时就重构出 `string, int, string`，以 `"r"` 为特殊值。
- 假设调用者未填写 `(mode)`，则 `command` 分导器**不会**在调用 `func` 时传回
  `("r", std::string(""))` 这个「号包」，从而简化输出逻辑，即只要识别是否有缺参数既可。

## 纸2 · Picocmd / WindowsPico / 重启接口

### 1. Picocmd

- Picocmd 是一个子项目，目的是**非 SWD、非自调试**，实现串口读写寄存器、内存、Flash、缓存、
  打断点、做 BOOTSET、强制重启等功能。
- Picocmd 为载荷提供以下函数：

1. **安全执行危险命令**
   调用此函数，Picocmd 会将当前状态存盘，在下次 `main` 函数的第一行插入断点，然后设置看门狗，
   占据 Core1 持续喂狗。一旦 Core0 执行超频等操作造成死机，机器随即重启。
2. **软件断点**
   Picocmd 的断点机制为：将某行指令改为跳转到断点函数的命令，并储存该行代码，在断点函数中恢复。
   断点函数也支持被载荷直接调用。
3. **协程 Core1 代码执行**
   Picocmd 主代码也有一份协程版，载荷可以申请递交一个协程函数在 Core1 运行。
4. **串口支持**
   Core1 独占了串口，载荷需将 `printf` 等操作发给 Picocmd，由它代为执行。
5. **PIO 重启**
   依靠主频 + 数数，PIO 也能作为定时唤醒 CPU。PIO 一来能作为看门狗失效的保险，二来能作为协程
   切换信号，同时处于**串口**的控制范围内。

- 一句总结（原文单独一行）：**「Picocmd 是现有后门调试器的最终升级。」**

### 2. WindowsPico

- WindowsPico 旨在运用电脑的强大算力模拟 Pico 的行为。它直接申请电脑 16MB 内存作为 Flash，
  16MB 内存作为 PSRAM（可选），520KB 内存作为 SRAM，利用 2 个逻辑处理器用 x86 强行模拟 Arm
  （是人能弄出来的？〔？〕）或 RISC-V。
- 它的最终成效就是结合 Picocmd，而**非局限于改内存**。
- 利用电脑的算力，完全可以再派一个核心读取内存中的寄存器值，调制 Picocmd 命令，真正实现操作。
- 虚拟化技术能让虚拟机的频率相较主机略有损失，处于 GHz 级。而 Arm 多种指令在 x86 中可简化，
  我们能够轻松得到 GHz 级的 Pico。**这显然是不行的**，所以存〔？〕要插入毫指令〔？〕，
  采取软降〔？〕方式降频到 MHz 级。

### 7. 重启

- **「现在的 Agent 个个都能重启 DSH，弄得鸡犬不宁。」**（红笔原话）
- 重启接口必须收敛，这是个好接口，但不好拿捏。
- 用户的重启接口延时不要了。
- Agent 的重启接口调用后并不立刻重启，而是通知**所有正在运行或有任务（所有）正在运行或有子
  Agent 正在运行的 Agent**。所有被通知的 Agent 都能调用以下 2 个功能：

1. `stopdshfromrestarting`
2. `allowdshrestarting`

- 1 号功能不用多说；当所有被通知的 Agent 调用 **2 号**功能后，重启才会开始。重启后，所有刚被通知的
  Agent 都会被通知。
- 同时，用户也要被通知。重启接口被调用后，用户随时在任意对话输入
  `/stopdshfromrestarting`，重启即停止。

### PIO 拆解

- 结论：若 n 个代码段长度分别为 `X1, X2, …, Xn`，若 `X1+X2+…+Xn+n < 32`，则可拼合。
  `+n` 代表 jmp 指令。
- 即一个 PIO 中的不同 SM 可自由选择跑哪个代码。
- 举个例子（`X1=3 条, X2=4 条, n=2`），合并后 **9 条**：

```
代码1            代码2            合并后
0 | xx           0 | YY           0 | xx
1 | xxx          1 | YYY          1 | xxx
2 | xxx          2 | YYY          2 | xxx
3 | …            3 | YY           3 | jmp 0
                                 4 | Y
                                 5 | YY
                                 6 | YYY
                                 7 | YY
                                 8 | jmp 4
```

- 若起点为 0，则 = 代码1；若起点为 4，则 = 代码2。
- 如此即可充分利用 SM。很多通信用 SM 只有 1 个指令，只要几条完全可以拼合，但 **jmp 指令会占时间**，
  需要考虑到。
- 旁注（原文）：**「* jmp 是我瞎写的，意思到了就行，别抄上去」**；另一处红笔：**「看这都是 SPI，实则全是 PIO」**。

### USB Hub 芯片

- 我认为在这里 USB 口为 3.0+，和 Pico 等设备通信口为 20 最好。
- 同时最好支持**双向逆传通信**〔？透传〕，即任意一口都能为主为从。主核的设计是根据外接设备**见人下菜**，
  可主可从；副核始终为从。
- 如果不行，副核的 USB 的 RX、TX 就作为触点。好了。
- 主核要被识别为「USB 集线器」，下有 2 个大容量移动存储设备：
  「对应烧录引导**伪磁盘** 128MB，用来 OBE 等系统应用」；
  另个则是真 SD 卡的映射，设插就没有。此外还要支持串口通信。
- 主核也要支持连接的 USB 耳机、USB 网卡、U 盘。
- 屏幕由于速度限制无需支持，也支持不了。
- 还要支持键盘、蓝牙键盘，通过 USB Hub 支持这些设备。

### DMA 管理

- 所有 DMA 通道都由内核按模块管理。
- 用户或内核其它部分向基〔？〕发送带 DMA 调用方式的通知。
- 模块分配 DMA 去完成，转发 DMA 消息、中断。
- 当 DMA 过于繁忙时，模块用 CPU **硬算**，并广播一条 DMA 忙消息。若状况持续，系统会打回低优先级
  DMA 请求。

### 蓝牙（组网与同步）

- 蓝牙要实现手动配对耳机，自动连接、重连。
- 还要支持自动连接其它设备，形成蓝牙组网。
- 支持从蓝牙组网自动下载整合消息、同步时间。
- 两设备以新近连过网、同步过时间的那个为准，默认发送接收时差为 0，即链路等长。
- 此外还有更新包：若两系统有一版新，两边即建立 WiFi 连接，否则点对点下载安装。
  **下载该立刻做，安装该通知用户**；应用同理，但可直接安装。
- **蓝牙组网**：若某一包本设备不可达时，便广播。收到者可达就达，否则广播。
  若关系固定，可记入路由表。过期能力作废，重试成功则续命。
