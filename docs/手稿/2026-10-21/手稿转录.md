3. `command` 注册

- `command` 的本质是一个表格，比方说 `std::vector`，其中的每一项都是一个**返回值为 `const char *` 的、
  输入为一个参数列表的函数**。〔图上在旁边标了 `template<?>`〕
- 参数列表是记录「(参数条件 + 参数)」的表格，该表格两项中任意一项都能为**特殊值**以指代万〔能〕。
- `addcmd(std::function<...>, 参数列表, funcname)`
  该输入列表包含了全部允许输入参数条件。为特殊值时，则意味着该位置允许无关参数存在。
- 例：

```
addcmd(std::function<…>, []{("r", std::string("")), ("r", 0), ("r", std::string(""))}, "gpio");
```

- `addcmd` 为抽象函数，每一项参数都自动实例化，而无论什么重例化，均可用其父类指针多态存储。
  此时就重构出 `string, int, string`，以 `"r"` 为特殊值。
- 假设调用者未填写 `(mode)`，则 `command` 分导器**不会**在调用 `func` 时传回
  `("r", std::string(""))` 这个「号包」，从而简化输出逻辑，即只要识别是否有缺参数既可。

## 纸2 · Pico cmd / Windows Pico / 重启接口

### 1. `Pico cmd`

- `Pico cmd` 是一个子项目，目的是**非 SWD、非自调试**，实现串口读写寄存器、内存、Flash、缓存、
  打断点、做 BOOTSET、强制重启等功能。
- `Pico cmd` 为载荷提供以下函数：

1. **安全执行危险命令**
   调用此函数，`Pico cmd` 会将当前状态存盘，在下次 `main` 函数的第一行插入断点，然后设置看门狗，
   占据 Core1 持续喂狗。一旦 Core0 执行超繁忙操作造成死机，机器随即重启。
2. **软件断点**
   `Pico cmd` 的断点机制为：将某行指令改为跳转到断点函数的命令，并储存该行代码，在断点函数中恢复。
   断点函数也支持被载荷直接调用。
3. **协程 Core1 代码执行**
   `Pico cmd` 主代码也有一份协程版，载荷可以申请递交一个协程函数在 Core1 运行。
4. **串口支持**
   Core1 独占了串口，载荷需将 `printf` 等操作发给 `Pico cmd`，由它代为执行。
5. **PIO 重启**
   依靠主频 + 数数，PIO 也能作为定时唤醒 CPU。PIO 一来能作为看门狗失效的保险，二来能作为协程
   切换信号，同时处于高口〔？〕的控制范围内。

- 用户的重启接口延时不要了。
- Agent 的重启接口调用后并不立刻重启，而是通知所有正在运行的任务（所有）正在运行的 Agent。
  调用这个函数可以获取当前正在运行的 Agent。

1. `stopdshfromrestarting`
2. `allowdshfromrestarting`
   - 1 号功能不用多说，指所有被通知的 Agent 调用该功能后，重启才会开始。重启后，所有被通知的

### PIO 拆解

- 结论：若 n 个代码段长度分别为 `X1, X2, …, Xn`，若 `X1 + X2 + … + Xn + n < 32`，则可拼合。
  `+n` 代表 jmp 指令。
- 即一个 PIO 的不同 SM 可自由选择哪个代码。
- 举例（`X1=3, X2=4, n=2`）：

```
代码1: | 0 0xx | 1 0xx |
       | 2 1xxx| 3 10xx|
代码2: | 4 0xx | 5 1xxx |
       | 6 1YY | 7 1YY |
```

- 若起长为 0，则 = 代码1；若起长为 4，则 = 代码2。
- 很多函数用 SM 没有几个指令，如此即可充分利用 SM。只要几条完全可以拼合，但 **jmp 指令会占用时间**，
  需要考虑。
- 旁注：**「这些都是 SPI，实则全是 PIO」**、`jmp` 是找地址、写〔？〕。

### USB Hub 芯片

- 我认为在这里 USB 作为 3.0+、和 Pico 等设备通信口为 20〔pin〕最好。
- 同时最好支持双向通信，即任意一口都能为主 / 从。主控的设计是提高外接设备（见下条），可主可从；
  副板始终为从。
- 如果不行，副板的 USB 的 RX、TX 就作为缺点〔？〕。
- 主板要能被识别为「USB 集线器」，下有 2 个大容量移动存储设备：对烧录引导的键盘 128MB，用来给 OBE 用；
  另个则是 SD 卡的映射。
- 主板也要持续接的 USB 耳机、USB 网卡、U 盘。
- 屏幕由于速率限制无需支持，也支持不了。
- 还要支持键盘、蓝牙键盘，通过 USB Hub 支持这些设备。

### DMA 管理

- 所有 DMA 通道都由内核按需分配管理。
- 用户或内核其它部分向基〔？〕发送 DMA 调用方式的通道。
- 模块分配 DMA 去完成，转发 DMA 消息、中断。
- 当 DMA 过于繁忙时，模块用 CPU 搬运，并广播一条 DMA 忙消息。若状况持续，系统会打回低优先级 DMA 请求。
