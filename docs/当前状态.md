## 三、上一轮修掉的两个 bug（**证据在这里，别处不重复**）

### 3.1 `kres_*_import` 不同步 SDK（真板 panic）

**症状**：`g_probe_marks` 停在 **116**，`g_kres_selftest_steps=29`、`status=0`、`fail_at=0`
⇒ 看起来像"第 29 步没跑完"，其实**崩在第 29 步的条件表达式里**。

**定位手段**（很好用，记下来）：在 `__assert_func` 上下硬件断点 → `reset` → `resume` →
读 **r0/r1/r2/r3**（分别是 文件/行号/函数/表达式 的指针）→ `dump_image` 那三段内存 → 读出字符串：

```
claim.c:51   hw_claim_clear()   assert(hw_is_claimed(bits, bit_index))
```

**根因**：`kres_dma_import()` / `kres_pio_sm_import()` 只写账本、**不调 SDK 的 claim**；
而 `kres_dma_release()` / `kres_pio_sm_release()` **无条件** `unclaim`
⇒ 真 SDK 的 `hw_claim_clear()` 断言"这位从没被认领过" ⇒ panic ⇒ `_exit()`。

**修法**：两个 `import` 都补上"先查 `*_is_claimed` 再 `*_claim`"（与 `kres_dma_claim` 一致）；
`kres_pio_sm_claim` 也补了查重（真 SDK 的 `pio_sm_claim` 走 `hw_claim_or_assert`，重复认领同样会断言）。

### 3.2 主机侧为什么没抓到它（**桩漏了契约**）

`tools/host_test/stub.c` 原来是 `void dma_channel_unclaim(unsigned int channel) { ... g_dma_claimed[channel] = false; }`
—— **无声赋值，没有断言**；而真 SDK 是 `unclaim → hw_claim_clear → assert(...)`。
⇒ **桩复现了【签名】和【状态】，漏掉了【契约】。**

**已修**：桩现在复现断言契约（`claim` 重复认领断言、`unclaim` 未认领断言，DMA 与 PIO 都补了）。
**并且按"先用必然失败的用例验检查机制"的顺序走过一遍**：
修桩 → 主机自检**失败**（`exit=-1073740791`）→ 修内核 → 主机自检转绿。

> 详细教训见 `陷阱本.md` **错 17**。

### 无限重启的根因（推理已验证，**未实测**）

`psram_writetest_run()` 把"步号标记"写在 `psram_reinitialize()` **之后**；
panic 若发生在那里面，标记永远写不进去，断点续跑机制就永远学不到东西
⇒ 每开机一次 panic 一次。
**重新打开这个实验之前，必须先把标记挪到 `psram_reinitialize()` 之前。**

## 五、待核实的矛盾

> **完整清单（含每条的双方原文）在 `陷阱本.md` 第四节**，这里只列与本文件状态表直接相关的。

1. **PSRAM 的失败模式**：`小本本.md` 记"连续写入挂死"，用户口述"随机读通过、连续块读写报 error"
   ⇒ **见 `陷阱本.md` M2**。⚠️ 仍待确认："报 error"是**返回错误码**还是**整片挂死**（两者根因不同）。
2. **SDIO 时钟脚** ✅ **源码层已结案（2026-10-04）**：`CLK = 30` 是对的
   （生成头 `rp2040_sdio.pio.h` = 22 ⇒ `(40 + 22) % 32 = 30`），`src/main.cpp:7` 的 `38` 是**过期注释**；
   ⚠️ 原提法"至少一处是错的"**不成立** —— `main.cpp` 那句 `CLK=30` 是**硬编码字面量、不读配置**。
   **物理层（GPIO30 有无时钟输出）仍未测。**（M3）
3. **MPU_CTRL 0 vs 5**：✅ **已定（不是矛盾）** —— 内核从不写 `MPU_CTRL`（`src/kernel.c` 只有宏定义）
   ⇒ 运行期恒为 0；崩溃后 `reset()` 进 bootrom，**5 是 bootrom 配的**。两个读数不是同一时刻的世界。
4. **目标板 USB 不枚举的原因**：两种说法口径不一致 ⇒ **见 `陷阱本.md` M4**（未裁决）。
5. **帧率**：8 秒出 38 帧 ≈ 5 fps，期望 ~60 fps —— 启动 + SD 初始化各占多少，**未单独测**
   （做法：连续两次读 `dvi0.dvi_frame_count` 做差）。
6. 🔴🔴 **系统调用机制（本文件 §二 模块表头一条的地基）**：`docs/应用ABI.md:488/497` 决策"**用写内存**"，
   而 `src/kernel.c:493-511` 写"**实测 4 轮后改用 SVC**"，本表 §二 记的是"**系统调用（SVC 版）✅ 上机**"——
   **全仓库找不到任何一处宣布写内存方案作废**，而 `需求本.md:38/41-50` 仍按写槽位记用户原话。
   ⇒ **见 `陷阱本.md` M8**，**待用户裁**（"本项目最终交付哪条路"）。（2026-10-04 `audit` 发现）
7. 🆕 **PSRAM `max_sel=18` 与规范 8「7.68 µs」对不上**（75 MHz 下若按周期算 ≈ 0.24 µs，差两个数量级）
