# 台架接口（pico_* 工具与 /pico 命令）

> **这份文档回答一个问题：一个刚接手的新对话，怎么知道这台台架上有什么接口、怎么用、以及哪里会咬人。**
>
> - 载体：DSH **Host 插件** `dsh-picophone`（不在本仓库里，在 `..\dsh-plugins\dsh-picophone\`）
> - 首次落地：**2026-10-06**（由 DVI 攻坚会话提出需求 → 另一个会话实现 → 本会话逐条实测验收）
> - 证据基线：`index.js` **2018 行**（改动后）、`serial-session.ps1` 258 行（行号会随改动漂移，引用时以函数名为准）
> - 覆盖面：**9 个 Agent 工具 + 1 个人侧命令 + 3 条横切机制（台架锁 / 烧写账本 / build_info）**，
>   并把每个工具的**全部失败分支**按原文抄录（§四、§五）
> - ⚠️ 本文只写**代码里真实存在**的行为与**本会话实测过**的结论；没测的一律标"未实测"
> - 📍 **先把位置弄清**：这些调用跑在 **Host 进程**里、**不是会话里的命令** ⇒ 会话的**文件策略与审批都不适用**于它们。
>   详见 **§十「这些调用归谁管」**（不弄清这条，会把"有围栏"误当成"被限制住了" ✗）

## 一、新对话怎么"发现"这套接口（三条通道）

| 通道 | 内容 | 谁提供 |
|---|---|---|
| ① **工具说明**（常显） | 9 个 `pico_*` 工具的参数与用法就写在工具定义里，模型一睁眼就能看到 | 插件 `index.js:1570-1758` |
| ② **系统提示注入**（常显） | 一段 `picophone:rig` 的短说明（**909 字符**），讲最会踩坑的几条规矩 | 插件 `index.js:1946-1985`（`RIG_PROMPT`），落点 `order=2705` |
| ③ **本文件 + `/pico`** | 细节看这里；人可以直接敲 `/pico help` | `index.js:1762-1781` |

**为什么还要 ②**：2026-10-06 全库 grep 实测 —— 项目自己的必读文件
（`开子Agent必读.md`、`..\子Agent须知.md`、`docs\工作守则.md`）里**一个字都没提 `pico_*`**，
26 处提及**全部**只出现在插件自己的 README 里 ⇒ 新会话会去手搓 `tools\serial.ps1` 那套旧流程，
白白错过台架锁与烧写账本 ✗ ⇒ 所以才往系统提示里补一段（每轮请求都进，因此刻意压到 909 字符）。

**②的两条硬约束**（改它之前先读）：
1. `RIG_PROMPT` 里**不许出现反引号** —— 外面是 JS 模板字符串，反引号会把字符串截断 ✗。
2. 注入**必须**用 `ctx.inject(['systemPrompt'], …)` 且**先判空**：
   - 用的是 `inject` 而不是直接 `ctx.systemPrompt.section()` ⇒ 服务没挂载时**静默不生效**，不会连累工具注册；
   - 2026-10-06 实测：不加判空守卫时，`smoke-test.mjs` 的假 ctx 没铺 `systemPrompt` 桩 ⇒ 当场抛
     `TypeError: Cannot read properties of undefined (reading 'section')`，**把 9 个工具一起带走** ✗。
3. 文本是**条件注入**：`pico_status` 没注册时返回空串（`index.js:1980`）—— 不能在说明里指着不存在的工具说话。

## 三、横切机制（三样，每个工具都受它们影响）

### 3.1 配置默认值（`DEFAULTS`，`index.js:43-99`）

| 键 | 默认 | 键 | 默认 |
|---|---|---|---|
| `root` | `C:\Users\Chen\Desktop\Pico\PicoPhone` | `lockStaleMs` | `600000`（10 分钟） |
| `repo` | `<root>\DeepSeekCode` | `profileName` | `''`（可手填，见 §七） |
| `tempRoot` | 系统 `%TEMP%` | `sessionIdleMs` | `120000`（2 分钟） |
| `powershell` / `python` | `pwsh` / `python` | `sessionOpenTimeoutMs` | `20000` |
| `timeoutMs` / `shortTimeoutMs` | `900000` / `120000` | `serialKeep` | `20`（自动落盘抓包留最近 20 份） |
| `maxOutputChars` | `14000`（前 60% + 后 40%） | `boardIds` | `dut: RP2350`、`probe: RPI-RP2`、`sampler: RPI-RP2` |
| `extraPath` | `[]`（空 = 自动探测 `~\.pico-sdk`） | `devices` | `dut` `2E8A:0009`、`probe` `2E8A:000C`、`sampler` `2E8A:000A` |

`allowExec` 共 **16 项**：`cmake, ninja, git, picotool, openocd, python, py, arm-none-eabi-{gcc,g++,objdump,objcopy,nm,size}, vswhere, msbuild, node`（`index.js:81-98`，比较时强制小写 `:167`）。
**`cl` 不在白名单**：它没有 VS 开发环境（INCLUDE/LIB）跑不起来；MSVC 那条路走 `pico_build host-test`（`index.js:79-80`）。

### 3.2 子进程 PATH 前缀（`discoverToolDirs()`，`index.js:105-156`）

扫 `~\.pico-sdk\{cmake,ninja,toolchain,picotool,openocd}`（首选版本排最前、其余按名倒序），
再用 `vswhere -latest -property installationPath` 补 VS 的 `MSBuild\Current\Bin`，结果前置进子进程 `PATH`（`:169`、`:745-752`）。

> **为什么必须有它**：这些名字**不在系统 PATH 上** ⇒ 不补就 `ENOENT`。
> 2026-10-06 实测：修复前 `pico_exec ninja` 报 `spawnError=spawn ninja ENOENT`，
> 而 `pico_status` 用绝对路径却显示 ✓ —— **同一件事两处口径不一致**；修复后两者一致。

### 3.3 硬超时 + 杀进程树 + 输出裁剪

- `runProcess()`（`:256-356`）统一 `windowsHide:true`；stdout/stderr 各封顶 **4 MiB**（`:286`）。
- 超时用 `taskkill /PID <pid> /T /F` **杀整棵树**（`:242-253`）—— 实测这是解决"死进程"的关键（`SerialPort.Open()` 被占用时会**永久阻塞**，见 §六）。
- 输出超 `maxOutputChars` 时保留**前 60% + 后 40%**（`:193-198`）；ANSI 转义剥掉（`:176-178`）；解码优先 UTF-8，失败退 GBK（`:180-191`）。

### 3.4 台架锁（串口/烧写互斥）

| 项 | 内容 | 位置 |
|---|---|---|
| 锁文件 | `cfg.lockPath`，默认 `$DSH_HOME\picophone.lock`（无 `DSH_HOME` 则 `~\.dsh\picophone.lock`） | `:457-461` |
| 获取 | `openSync(file,'wx')` **独占创建** | `:531-537` |
| 内容 | `{token,pid,session,profile,what,since,sinceText}` | `:521-530` |
| 陈锁① | `now - since > lockStaleMs`（默认 10 分钟） | `:543` |
| 陈锁② | 占用进程已死（`process.kill(pid,0)` 抛非 `EPERM`） | `:544`、`:463-470` |
| 陈锁处理 | **只在第 0 轮尝试**删锁重试（共 2 轮） | `:545-552` |
| 占用文案 | `台架被占用 ✗ …` + 占用者（what·pid·会话·profile·起于·已占用 Ns）+ 锁文件路径 | `:553-560` |
| 释放 | `releaseRigLock()`：读到锁文件且 **token 相同**才删 | `:566-574` |

> 🗓 **2026-10-07 修正：该脚本已【退休】，只诊断、不再删锁** ✗ —— 因为 `pico_run` 自己也进了沙箱（§10.7）⇒ 它**删不动**工作区外的锁 ✓
> 现在它只报 `VERDICT = FREE | HELD | STALE | UNREADABLE` 与占用者，并指向 **`/pico lock clear`**（由插件在 Host 侧删 ✓）。
> ⚠️ 另有实测坑：沙箱子进程**没有** `$DSH_HOME` ⇒ 旧版会回落到 `C:\Users\Chen\.dsh\` 并报**假 FREE** ✗（见 §10.7 第 2 条）
> **正确用法（2026-10-07 起）**：删锁走 **`/pico lock clear`**（人侧）✓；查锁走 `pico_run tools/clear_rig_lock.ps1`（只读诊断 ✓）

**占锁的**：`pico_flash`（真刷，`:1195`，`finally` 释放 `:1226`）、`pico_serial`（非 list，`:1306`，`finally` `:1316`）、
`pico_console` 的 `open`（`:835`；`close`/子进程退出/空闲超时释放 `:936`、`:875-879`）。
**不占锁的**：`pico_status`、`pico_build`、`pico_temp`、`pico_git`、`pico_run`、`pico_exec`、`pico_flash method:'list'`、`pico_serial list:true`。

> **实测（2026-10-06）**：会话持有锁时另一个 `pico_serial` 被硬拒并报出占用者；
> `close` 后锁消失；**空闲 150 秒后自动释放**（T+0 有锁 → T+150 无锁）✓

## 六、会咬人的坑（先读这一节，能省半小时）

1. **`empty.uf2` 不能当中转固件** ✗ —— 它**不开 USB stdio**（`src\empty.c` 只 `tight_loop_contents()`，
   `CMakeLists.txt` 里 `pico_enable_stdio_usb(empty 0)`）⇒ 烧上去**既没串口也没后门**，只能手按 BOOTSEL 救。
   要中转请用 **`backdoor_only`**（2026-10-06 新建：USB CDC + 后门活着，别的什么都不干）。
   **实测证据**：`empty.uf2` 里搜不到任何后门字符串；`backdoor_only.uf2` 里能搜到 ✓
2. **`tools\flash_backdoor.ps1` 对所有串口无差别猛发 6 次 `B`** ✗（`:79-93`）——
   实测它打印 `已向 COM1 发送 B`、`已向 COM8 发送 B`（**COM8 是探针**）。
   探针这次没事只因为**它的后门要求 `ESC ESC` 前缀**；换一版探针固件就可能被推进 BOOTSEL，
   而**探针现在跑的后门版固件盘上已无备份** ⇒ 那个方向烧坏就回不来。
   建议：只对 VID/PID 匹配目标板的那个口发 `B`。
3. **本台架没有 RUN 引脚、SWD 不可用** ⇒ **BOOTSEL 按钮是唯一救砖手段**。
   所以任何要烧进板子的固件**必须自带串口后门**（DUT：单键 `B`=进 BOOTSEL、`R`=重启）。
4. **`SerialPort.Open()` 被占用时会永久阻塞**（`serial-session.ps1:25`）⇒ 必须靠硬超时 + 杀进程树兜住。
5. **worker 参数名不能叫 `-Pid`**（`$PID` 只读 ⇒ 端口静默变空串，报 `The PortName cannot be empty`）——
   项目里已经踩过两次，现在叫 `-ProductId`（`serial-session.ps1:26`、`:50-52`）。
6. **时间戳必须按"到达时刻"打**：只在收到 `read` 时才排空端口，会把积压挤成一坨、时间戳骗人（`serial-session.ps1:9-13`）。
7. **smoke test 对 `process.env.DSH_*` 的结论与真实运行相反** ✗ ——
   Host 进程 env 里**没有** `DSH_SESSION_ID`/`DSH_PROFILE`（Harness 只注入给派出去的子进程），
   而 smoke 自己就是子进程 ⇒ 它测出来 `profile=web`，实际 Host 写出来是 `''`。
   ⇒ 凡是读 `DSH_*` 的分支，**必须上机/上 Host 验**，别拿 smoke 当证据。
8. **schema 里没有 `default` 关键字** —— 工具描述里写的默认值只是文字，真值只存在于 `op*` 代码里；
   改默认值要改代码（`:1079`、`:1294`、`:1342`…），改描述没用。
9. **`pico_status` 的 SDK 路径是硬编码 `sdk\2.3.0`**（`:992`）⇒ 升级 SDK 后状态页会指错地方（工具链版本表不含 SDK）。
10. **`pico_flash` 的预检文案像报错**（见 §4.3 末尾）—— 看到 `没看到任何 BOOTSEL 盘` 不代表失败，往下看有没有 `已刷入`。

| `pico_serial` / `pico_console` / `pico_flash` / `swd` / `procs` / `pico_status` 的 proc_guard | **窗口外**（豁免：串口、烧写、进程守卫）| 这些调用点**没有** `sandbox: true` ✓ |
| 台架锁 / 烧写账本 / `build_info` / 串口抓包 | **插件自己写**（Host 进程，不走 ACL）| `index.js` 里那十几处固定 `writeFileSync` ✓ |

**为什么 build 被移回窗口外** ✗：沙箱里 cmake configure 会以 `0xC0000005`（访问违例）崩，
而外层退出码被 `ninja: no work to do` 洗成 0（正是项目自己的"假成功"坑 ✗）⇒ 两次复现后改回 ✓

**沙箱内必须自己做的三件事**（写命令串时最容易漏）：
1. **注入 PATH** —— `ctx.shell` 用的是**它自己的系统 PATH**，`ninja` / `arm-none-eabi-*` 都不在里面 ✗
   （`cmake` 恰好在系统 PATH 上 ⇒ **只测 cmake 会误判成"能跑"** ✓）
2. **注入 `DSH_HOME` / `DSH_PROFILE`，且必须强制单引号** —— 沙箱子进程**没有**这两个变量，
   依赖它们的脚本会回落到假路径（`clear_rig_lock` 曾在 `C:\Users\Chen\.dsh\` 上报**假 FREE** ✗）；
   而裸词赋值 `$env:DSH_HOME = C:\固态盘秘钥\.dsh;` 会被 PowerShell **当成命令**执行 ⇒ 变量根本没赋上 ✓
3. **输出必须"直通"** —— 在 pwsh 里捕获原生输出（`& exe | cmdlet`、`$x = & exe`）会走 `\\.\pipe\LOCAL\dotnet_*`，**沙箱拒** ✗

**git over HTTPS 在沙箱内怎么通的**（**不需要开任何沙箱例外** ✓）：
- **TLS**：本机装了 Watt Toolkit（MITM 代理）⇒ 把它的根证书导成**工作区内的 PEM**，再
  `-c http.sslBackend=openssl -c http.sslCAInfo=<pem>` ✓ **别用 schannel**（它要访问用户加密存储 ⇒ `SEC_E_NO_CREDENTIALS` ✗）
- **凭据**：`-c http.extraHeader=Authorization: Basic <b64>`，令牌由**插件自己**读 `$DSH_HOME\.git-token` ✓
  ⇒ 不落工作区、**不进会话日志** ✓（**本会话复核**：`describeRun` 只打净化过的 `label`，**不打 `result.command`** ⇒ 含令牌的命令串不会被打回上下文 ✓）
- 已知边界 ⚠️：沙箱里凡要 POSIX shell 的 git 操作（凭据提示脚本）会建命名管道被拒 ✗，
  且那些报错行会**攒到 DSH 主进程退出时**才吐出来 ✓

**插件源码现在在版本控制里了** ✓ —— 这是 10.6「最后一道防线是**插件源码可审**」的前提：
```
C:/…/PicoPhone/DeepSeekCode   [deepseek_bunch]    ← 主线
C:/…/PicoPhone/dsh-plugins    [dsh-plugins]       ← 同一仓库的孤儿分支 + worktree（改插件要在这里提交）
```

### 10.1 它在哪跑

9 个工具与 `/pico` 都由插件在 **DSH Host 进程里直接 spawn**（`index.js:12-14` 自述）。
它**不经过会话 shell**（`pwsh` / `bash` 那条路），因此**不进入会话的文件策略与审批链** ——
这是它的**定义**，而不是它绕过了什么 ✓

### 10.2 由此产生的两个"不适用"（2026-10-06 22:0x 同刻 A/B 实测）

| 策略 | 对**会话 shell** | 对**台架接口** |
|---|---|---|
| 文件策略（当晚 = `workspace-write`）| 写工作区内 ✓；写真实 `%TEMP%` ✗ 被拒；写 `$DSH_HOME` ✗ 被拒 | **不适用**：同一时刻 `pico_build` 照常写盘 ✓、`pico_console` 照常在 `$DSH_HOME` 建台架锁 ✓、`pico_temp` 照常写真实 `%TEMP%` ✓ |
| 审批策略（当晚 = `ask`）| 会触发审批 | **不触发**：当晚十几次 `pico_*`（含真构建、开串口、`pico_exec` 跑内联代码）**一次审批都没弹** ✓ |

⇒ 一句话：**收紧会话 ≠ 收紧台架接口** ✓ 想收窄它只能收窄**插件暴露给 agent 的参数面**（见 §10.5）✓

### 10.3 那它受什么约束（三条；都不是"安全边界"，别当墙用）

1. **它自己的围栏（防手滑，不防恶意）**：`pico_exec` 可执行文件白名单 · `pico_run` 脚本目录白名单 ·
   `pico_temp` 的 `%TEMP%` 围栏 · `pico_flash` 的盘身份核对 · `pico_git` 的写动词闸门 ✓
2. **台架锁 + 烧写账本**：让"谁在什么时候占了台架、烧的是哪一份"**可查** ✓
3. **人在看**：每次调用都出现在界面上、可以随时打断 —— **这是唯一真正防恶意的机制** ✓

### 10.4 诚实的能力描述（写给下一个接手的人，免得误判）

- `pico_exec` 的白名单含 **`node` / `python` / `py`**，而它们本身就是**任意代码解释器** ⇒
  `pico_exec node -e "…"` 等价于一条任意命令 ✓（`index.js:81-98`；注释 `:60-61` 写"不放 shell"，口径需与事实对齐）
- `pico_run` 校验的是**脚本路径**落在 `tools/` 或 `dsh-plugins/` 内（`index.js:1451-1453`）⇒
  **对这两个目录有写权限的人可以先放脚本、再借 Host 的手执行**（脚本**内容**不校验）✓
- `pico_git` 的写动词闸门是**黑名单**（拦 19 个动词，`index.js:1431`）⇒ 全局选项如 `-c alias.<名>=!<命令>`
  不在其列，而 git 会真的执行它 ✓
- ⚠️ 但**不要把这些叫"漏洞"** ✗ —— **"能构建"本身就是"能执行代码"**（cmake/ninja 的本质就是"读文件、执行里面的命令"），
  砍掉这些能力等于砍掉干活的能力 ✓ 它们属于**能力的必然代价**；记在这里的目的只有一个：
  **别误以为这里有一堵墙** ✓

### 10.5 两处"描述与实现不一致"（改文字即可，不必收窄能力）

| 处 | 描述**声称** | 实际 | 建议 |

| `pico_serial` 的 `outFile` | 参数描述写"相对路径解析到 `%TEMP%` 下" | **绝对路径原样透传**（`index.js:1297` 只围栏相对路径）| 描述改成"**绝对路径会原样透传**" ✓（让人知道它不是围栏）|

### 10.6 想真正收窄时，改哪里（供参考，未实施）

收窄**参数面**而不是砍能力：① `pico_exec` 对 `node`/`python`/`py` 拒绝内联代码参数（`-e`/`-c`/`-m`/`-`），
