## 一、开工四步（照做，别跳）

1. **先看台架**：`pico_status`（人可敲 `/pico status`）—— 一屏给全：工具链版本 / git 干净否 / 2E8A 设备 /
   **台架锁被谁占** / **最后烧的是哪一份固件**。
2. **动手前扫清单**：`docs/开工前自检.md`（约 1 分钟，**动手清单的唯一入口**；每条命中都能去 `docs/陷阱.md` 查同名编号）。
3. **要写状态/结论时**：先看 `docs/当前状态.md` 的写法 —— **带证带期**（哪次实测 / 哪个变量 / 哪个 commit + 日期），
   写不出来就写"**待查**"，不许写成结论。
4. **要派子智能体时**：先读仓库根 `开子Agent必读.md`，并跑
   `pwsh -NoProfile -File tools/who_can_i_reuse.ps1 -ShowMain` —— **先看有什么能复用的，再决定新建**。

> 想了解**用户是什么样的人 / 项目全貌** ⇒ `docs/导引.md`；用户要求 ⇒ `docs/需求.md`；规矩与文档分工 ⇒ `docs/工作守则.md`。

## 二、台架接口（2026-10-06 新增，最省时间的东西）

9 个一级工具 + 人侧 `/pico`：`pico_status` / `pico_build` / `pico_flash` / `pico_serial` /
`pico_console` / `pico_temp` / `pico_git` / `pico_run` / `pico_exec`。
**先调 `pico_status`，不要手搓 `tools\` 下的旧命令**（旧流程没有台架锁、也不记账本）。

- **串口与烧写互斥**：两者都占**台架锁**（`$DSH_HOME\picophone.lock`），并发会被明确拒绝并报出占用者；空闲 2 分钟自动关会话并释放。
- **按键驱动的固件用 `pico_console`**：`open` 一次只付 4~5 秒开口成本，之后 `send`/`read`/`expect` 很便宜；`expect` 支持 `until` 正则，不用猜睡眠。
- **烧写纪律**：这块台架**没有引出 RUN 引脚** ⇒ **BOOTSEL 按钮是最后的救援手段**。要烧的固件**必须自带串口后门**（`B` = 进 BOOTSEL，`R` = 重启）。
- **"板上现在跑的是哪一份"**：看 `pico_status` 的「最后烧写」—— 记在 `debug_logs\flash_ledger.jsonl`，含 uf2 的 sha256 前 16 位与源码 commit。
- **每个工具的参数、行为与全部失败分支**（含 10 条会咬人的坑）⇒ **`docs/台架接口.md`**。

## 三、五条最贵的规矩（每一条都真被违反过）

1. **"我以为" ≠ "我量过"** —— 说之前先能指到哪一条实测数据。
2. **状态/结论必须带证带期**；写不出来只能写"待查"（`docs/工作守则.md` §二）。
3. **看到"✅ 通过"先问一句**：这是**主机侧**，还是**板子上**？
4. **要烧板子之前先自问：不用按键、不用手，能救回来吗？**
   ① 有 SWD/调试器可控 ⇒ 不强制要后门；② **没有 SWD**（如探针自己）⇒ **必须**有后门，且**没实测过的后门不算后门**；
   ③ 两者皆无 ⇒ **绝对不许烧** ✗✗。另外：**没试过的时钟频率不要试**（见 `docs/陷阱.md` 错 26）。
5. **本项目头号风险是"记混了"，不是"技术太难"** —— 过时信息比缺失信息更贵；
   改文件名/术语时**必须连带改引用**（判据 `tools/check_docs_refs.py`）。
