# 图形化/屏幕操作能力（2026-11-01）

目标：让 Agent 能**看见并操作**桌面窗口，同时**尽量不打扰正在用电脑的人**。

核心思路是**分层**：能拿到结构就不碰像素，能后台触发就不动鼠标。

---

## 一、动作优先级（从最安静到最吵）

| 顺序 | 方法 | 是否抢焦点 | 适用 |
|---|---|---|---|
| 1 | **UIA Invoke**（`uia-invoke.ps1`） | ❌ 不动鼠标、不改前台 | Win32 / UWP / WPF 等有 UIA provider 的控件 |
| 2 | **CDP click**（`cdp.mjs`） | ❌ | 浏览器 / Electron 的网页内容 |
| 3 | 坐标点击（`click-at.ps1`） | ✅ **会抢焦点** | 自绘 UI、canvas、游戏 |

> 实测结论：**计算器上 UIA 完美**（47 个控件，带 `AutomationId`），
> 点「七」显示即变 7；`CalculatorResults` 还能直接读到结果文本 —— 连像素都不用比。

## 二、脚本清单（`DeepSeekCode/tools/gui/`）

| 脚本 | 作用 | 关键点 |
|---|---|---|
| `list-windows.ps1` | 列窗口 | **cloaked 的直接过滤**（别的虚拟桌面/挂起的窗口，抓不到也没意义） |
| `capture-window.ps1` | 按窗口截图 | 见下方「三个坑」 |
| `zoom-at.ps1` | 放大镜 | 给一个点，返回带红十字的放大图 + `origin`（可换算回绝对坐标） |

## 三、三个坑（都是实测踩出来的）

### 1. cloaked 窗口抓不到 —— 而且会返回**假图**
别的虚拟桌面/已挂起的窗口，`DwmGetWindowAttribute(DWMWA_CLOAKED)` 非 0。
此时 `PrintWindow` 全黑，而**屏幕截取会抓到它位置上的桌面壁纸**——一张"看起来很成功"的假图。
⇒ 现在**直接拒绝**（`exit 6`），并说明"它不是抓不到，是不在这个桌面"。

### 2. WinUI3 的 PrintWindow 返回**旧帧**
记事本（Win11 新版）对 `PrintWindow` 返回上一次的画面：键盘已经打进去了，截图还是空白。
⇒ 校验时用 `-PreferScreen` 走屏幕截取；`verify-action.ps1` 会自动判断"窗口是不是前台"来决定用哪种。

### 3. 屏幕截取只对"真的看得到"有效
不是前台就拒绝（`exit 4`），**不返回假图**。`-Raise` 是显式选项（会抢焦点）。
前台锁（`SetForegroundWindow` 被系统拒绝）在普通后台进程上很常见，
`SwitchToThisWindow` / `AttachThreadInput` 也不一定管用——但**非 cloaked 的普通窗口 `SetForegroundWindow` 实测可用**。

## 四、虚拟显示器（Parsec VDD）

- 驱动：`parsec-vdd 0.41`（**已签名**，Win10 22H2 可用，不用开测试签名）
- 设备接口：`\\?\ROOT#DISPLAY#0000#{00b41627-04c4-429e-a26e-0265cf50c8fa}`
- ioctl：`ADD=0x0022e004` `REMOVE=0x0022a008`（16 位大端 index）`UPDATE=0x0022a00c`
- **必须保活**：<100ms ping 一次，否则约 1 秒后自动拔出
- 保活进程用 `vdd.ps1 -Serve`；**同时只能有一个 keeper**（两个并存会出现"进程在、屏不亮"的空转）

结果：多出 `\\.\DISPLAY19 1920x1080 @1920,0`，Agent 的窗口放上去，用户主屏不受打扰。

⚠️ 重启 DSH 会杀掉 keeper（它是子进程），**重启后要重新拉起**。

## 六、快速验收

```powershell
# 1) 虚拟屏在不在
pwsh -File tools/gui/vdd.ps1 -Status
# 2) 起个窗口放到虚拟屏（用户看不见）
pwsh -File tools/gui/launch-on-vd.ps1 notepad.exe
# 3) 看控件
pwsh -File tools/gui/uia-tree.ps1 0x1234 -OnlyClickable
# 4) 按 id 点（不动鼠标）
pwsh -File tools/gui/uia-invoke.ps1 0x1234 -AutomationId num7Button
# 5) 证明生效
pwsh -File tools/gui/verify-action.ps1 0x1234 -Command "pwsh -File tools/gui/click-at.ps1 2000 300"
```

## 七、UWP 启动会先在主屏闪一下

`Start-Process 'calculator:'` 之类会**先在主屏创建窗口**，再被 `place-window.ps1` 挪到虚拟屏——
中间那一两秒用户是能看见的（用户实测："挡着我了"）。

缓解方向（未实现）：
- 启动后立刻 `ShowWindow(SW_MINIMIZE)`，再挪、再还原；
- 或给 UWP 用 `ApplicationFrameHost` 的窗口句柄一次性定位；
- 最稳的是**只启动我们自己控制的程序**（浏览器带 `--window-position` 就不会闪）。

## 八、又一个坑：虚拟屏不能频繁插拔

每 `ADD` 一次虚拟显示器，Windows 会**重新排布所有窗口**。所以：
- **不要为了修 keeper 反复重启它** —— 用户感受到的就是"到处弹窗"；
- keeper 现在有**启用开关**：`%TEMP%\picophone-vdd.enable` 不存在就直接退出、不插屏；
- 要开虚拟屏：先建开关文件，再起一次 keeper，之后**不要动它**。

```powershell
New-Item -ItemType File "$env:TEMP\picophone-vdd.enable" -Force | Out-Null
pwsh -File tools/gui/vdd.ps1 -Serve    # 后台起一次即可
```

## 九、提权程序挪不动（别拿它做测试）

`regedit.exe`、`mmc.exe` 这类会**自动提权**，非提权进程 `SetWindowPos` 会被拒绝
（表现为 `[place] 挪动没生效：想去 1960,40，实际 339,225`）。
选测试目标要么用非提权程序，要么让 DSH 自己提权运行。

## 十、最小化启动不可靠

`ProcessStartInfo.WindowStyle = Minimized` 能让程序不在主屏闪，但这类窗口的 rect 是
`-32000,-32000`，**还原之前挪不动**，而且还原后位置仍可能不生效。
结论：**回退成普通启动**，接受 1 秒左右的闪烁；UWP 的闪烁问题仍待解。
