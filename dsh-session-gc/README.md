# dsh-session-gc

清理**空草稿会话**。

## 为什么需要

2026-11-06 实测：780 个会话里 **617 个是空草稿**（79%），只有会话头和策略事件
（`session` / `permission/preset` / `sandbox/mode` / `approval/policy` / …），**没有任何消息**。

它们只占 0.5 MB，省空间没有意义；真正的代价是**数量噪声**：

- `dsh-restart` 按文件 mtime 判"忙" ⇒ 空草稿被拉进投票名单、还会被唤醒
  （已踩过：用户看到窗口里凭空冒出一个会话在投票，以为插件乱开窗）；
- 会话列表、按会话扫描的统计都被 79% 的空壳稀释。

## 判定条件（只有一条 + 三道保险）

1. 解出来的事件里**没有任何** `user/message`、`assistant/message`、`turn/start`；
2. 文件 **≥ N 小时没动**（默认 6）：避免删掉用户刚打开、正要开始打的会话；
3. 跳过**当前会话自己**；
4. **坏帧一律不动**（解不开说明状态可疑）。

## 删除 = 移动，不是抹除

移到 `%DSH_HOME%\trash\session-gc\<时间戳>\<会话 id>\`。
要恢复：把文件夹搬回原工作区目录（`%DSH_HOME%\sessions\<--工作区编码-->\`）。
确认无用后直接删掉那个批次目录即可。

## 用法

| 工具 | 作用 |
|---|---|
| `session_gc_scan({minAgeHours})` | 只报告，不动磁盘 |
| `session_gc_apply({apply:true, minAgeHours, maxSessions})` | 真的移动；**不传 `apply:true` 就是 dry-run** |

命令行：`node index.js --scan 6` / `node index.js --apply 6`。

## 首次清理结果

780 → **171** 个会话（移走 609 个，535.8 KB），有对话的 163 个全部完好。

## 根因提醒

空草稿不是这个插件造的，是 Web GUI 在打开页面/重连时创建、且从不清掉的草稿会话。
本插件只是**兜底清理**；要根治应在 GUI 侧（关闭时删除未使用的草稿，或干脆延迟创建）。
